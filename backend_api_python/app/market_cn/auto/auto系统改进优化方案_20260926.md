## 0. 系统本质（设计意图 vs 现实）

三层结构，三条执行路径必须同源：

```
core/data/hub  ←  core / features  ←  strategies  ←  registry  ←  scan·monitor·core/backtest  →  store  →  api
```

| 文档意图（IDE 架构 / 系统设计） | 现实（2026-09-26 实测） |
|---|---|
| 一个 YAML 一个策略，`.py` 只是逃生舱 | 双实现并存，**生产走 `.py`**，YAML 是「逐字镜像」副本 |
| 策略互不依赖；core 不认策略 | `break_v2→break`、`triple_resonance→v1`；**core 反向 import 策略私有引擎** |
| 出场语义唯一实现（`core/exec`） | 原语唯一，但**出场引擎 5 份副本** |
| 新策略 = 一个 `.py` + config 一行 | 实际 400–1100 行（含镜像 helper + 回测引擎） |
| 20 策略规模预案（批量取数等） | monitor 批量未做；复制样板会先炸 |
| `dragon_v2/break_v2` 2026-09-13 撤回 | `dragon_v2.enabled=true` 仍开着 |

**模块体量**：strategies/ 8062 行 · tools/ 6826 行 · 入口编排 3899 行 · core/runtime 1746 行 · rebuild 1037 行。

## 1. 策略文件：重复的半成品（独立性不足）

### 1.1 每个文件 = 两套半成品粘在一起

| 策略 | 总行数 | 插件私有 helper | YAML 门函数镜像 | 镜像方式 |
|---|---|---|---|---|
| knife_catch | 496 | `_hhmm` `_tail_ret`… | `_kc_hhmm` `_kc_tail_ret`… | 注释写明「逐字镜像」 |
| tail_oversold | 410 | `_calc_score` `_tail_ret_v2`… | `_to_calc_score` … | 同上 |
| break | 1091 | `_break_signal_at`… | `_bk_*` 尾部约 200 行 | 同上 |
| g56 | 1039 | 25 个私有函数 | 8 个门函数 | 同上 |

**症结**：一个文件里同时住着「生产插件判定」和「YAML 门表适配层」，改一处必须人肉同步另一处。

### 1.2 出场 / 回测引擎复制 5 份（约 3200 行）

T+1 / 跳空开盘成交 / 跌停顺延，近似副本散落在：

- `dragon_callback.py:400-500`、`dragon_v2.py:231-328`、`dragon_callback_legacy.py:252-358`
- `v1._run_backtest`、`break._run_backtest_breakbuy`、`g56._exit_no_trail`、`relay3.run_backtest_relay3`

`core/exit_modes.py` 名义上收敛，实际是**策略 import 垫片**（`exit_modes.py:29-34` 转调上述私有引擎）。

### 1.3 脚手架复制 ×6

| 样板 | 出现次数 |
|---|---|
| `_signal_to_legacy_dict` + `_find_bar_idx` | 6 |
| `confirm_decision` signal_price 基准样板 | 6 |
| `backtest_stock` 枚举脚手架（dedup→U1~U4→引擎→trades） | 6 |
| `exit_decision` day_close 重放包装 | 3+ |

### 1.4 策略间互相 import（违反「禁兄弟依赖」）

- `break_v2.py:40-44` → `strategies.break`（BOARD_PARAMS / `_run_backtest_breakbuy`）
- `triple_resonance.py:429,516` → `v1._run_backtest`
- `dragon_v2` = `dragon_callback` 快照分叉（779 行独立拷贝）

### 1.5 层反转：core 反向依赖 strategies ⚠️ 最严重

```
core/exit_modes.py:32-34,119     → dragon_callback / relay3 / v1 / g56 私有引擎
core/runtime/evaluate.py:44,726  → relay3_features / g56._ensure_pool_daily
core/present/pipeline.py:299     → g56._ensure_pool_daily / _g1_arrays
```

文档 §2.2 写明 `core/*` 禁止依赖 strategies——**依赖方向红线已被击穿**。20 策略时这里会变成 20 条硬编码耦合。

### 1.6 半成品 / 死代码清单

| `dragon_callback_legacy.py` 743 行 | 无 config 键，永久黑暗；还写 `path="dragon_callback"` |
| `dragon_v2` enabled=**true** | config 注释写「2026-09-13 撤回 V2」，代码没关 |

## 2. 框架 / 工具链 / 重建

### 2.1 高复杂度热点

1. **`evaluate.py` 重抄每个策略的编排**——`day_flow ∈ {v1,relay3,break,g56}` 四个 `_run_backtest_day_*` 逐字镜像插件；策略常量烧进 core（dedupe ±4、`max_break_gap`、g56 lock、北交所过滤）。
2. **U1~U4 + 去重 + daily_limit 后处理抄了 4 份**：`scan.py:202-231`、`scan.py:358-385`、`rebuild.py:210-241`、`core/backtest.py:376-391`。
3. **rebuild 两套写库管线**（signal 层 + ledger 层）+ 3 套渲染；「停用策略作废」SQL 存在 3 处（`rebuild.py:350-363`、`rebuild.py:697-708`、`startup.py:430-447`）+ monitor 开窗再一份。
4. **g56 池双算**：`present/pipeline._g56_pool_batch` 与 `g56._ensure_pool_daily` 必须「完全同口径」镜像。
5. **CN 常量漏出 MarketSpec**：北交所 `startswith(("8","4","92"))` 写在 rebuild/pipeline/evaluate 三处。
6. **`store.upsert_scan_signals` 契约陷阱**：`DO UPDATE SET state` 会把 holding 打回 watch_pending，rebuild 只能绕开。
7. **21 个 tools 无一键调试入口**：`explain`↔`gate_funnel`、`rule_audit`↔`rule_stats`、`debug`↔`replay` 各有重叠。

### 2.2 模块肥胖度

| 模块 | 行数 | 模块 | 行数 |
|---|---|---|---|
| rebuild.py | 1037 | store.py | 779 |
| startup.py | 716 | evaluate.py | 780 |
| pipeline.py | 849 | strategies/ 合计 | 8062 |

## 3. 扩展到 20 策略，先断的是什么

**不是 scan/monitor**——已注册表泛化，20 个能跑。先断的是：

1. **复制增长**：每个新策略重实现 200–400 行出场/回测/confirm 样板 → 漂移（已有实例：`break_v2` 的 score 仍 `int(confirm_chg)+10`，与 `break._score_of` 不一致）。
2. **core 硬编码策略钩子**（exit_modes / evaluate / present）。
3. **YAML+.py 双源**：改动面 ×2。
4. **g56 式单槽池缓存**：2–3 个横截面策略即抖动。
5. **config 单文件 20 键** + schedule 只覆盖 3 个。

## 4. 改进方案（按优先级）

### P0 止血（半天级，不改架构）

| # | 做什么 | 消掉什么 |
|---|---|---|
| 1 | `dragon_v2.enabled=false`（或注释说明为何重启） | 开关不一致 |
| 2 | `del/` 收编 `dragon_callback_legacy`、孤儿 pyc、`base.py` 死 stub | 半成品 |
| 3 | `store.retire_unfilled()` 统一，删 3 份重复 SQL | 3 处漂移 |
| 4 | `postfilter_signals()` 抽出 U1~U4+去重+限额，4 处调用 | 4 处漂移 |
| 5 | `qd doctor`：config↔注册表↔库活跃行 三方对账 | 「关了还在跑」假象 |

### P1 策略文件独立化（核心，支撑 20 策略）

| # | 做什么 | 目标形态 |
|---|---|---|
| 6 | **消灭文件内「逐字镜像」**：YAML 门函数直接调插件 helper（或 helper 下沉 `core/`），不再复制 | 一个策略一份判定逻辑 |
| 7 | **出场引擎上收**：5 份私有引擎 → `exit_modes` 参数化模式（combo/trail/stop/signal），策略只声明 `exit:` 配置 | 策略文件 50KB→5–15KB |
| 8 | **回测脚手架上收**：`backtest_stock` 枚举/dedup/U1~U4/trades 构造进 base 通用引擎；策略只留 `scan_signals` + 参数 | 新策略 = 100–300 行 |
| 9 | **切断层反转**：`exit_modes`/`evaluate`/`present` 不再 import 策略私有函数；g56 池 → `core/features/cross_section.py` | core 零策略知识 |
| 10 | 版本链改「继承/组合」替代 `break_v2 import break`；`dragon_v2` 分叉要么 merge 回 dragon 要么标实验隔离 | 禁兄弟 import |

### P2 重建 / 调试瘦身

| # | 做什么 |
|---|---|
| 11 | rebuild 只留 ledger 一条写路径 + dry-run 报告；删 signal 层 apply |
| 12 | 状态机（pending→buy→hold→exit→closed/expired）从 monitor 注释抽成单一模块 |
| 13 | `qd why <code> --date D --strategy S`：门级 TRACE 一体化；`qd diff`：改规则后秒级信号集 diff |
| 14 | CN 常量收进 `MarketSpec.board_rules` / `is_tradable(code, spec)` |

### P3 规模化收尾（20 策略前）

| # | 做什么 |
|---|---|
| 15 | YAML 真正成为门表类策略的**生产路径**（与 present 同源），`.py` 退为逃生舱（g56/knife/tail 这类） |
