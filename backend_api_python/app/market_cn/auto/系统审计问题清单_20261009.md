## 1. 逻辑缺陷

### L-1 🔴 盘中状态机接线断裂：scheduler 调用不存在的 `run_monitor_safe`
- `app/market_cn/scheduler.py:363-364` `from ...monitor import run_monitor_safe`；`monitor.py:389` 只有 `def run_monitor()`，全仓无 `run_monitor_safe`。
- 后果：Task `dragon_monitor` 每 60s 触发即 ImportError，被 `_worker` 的 `except Exception` 吞掉 → **开盘 gap 买入、盘中止损、预确认、收盘出场、15:01 确认、平账整条盘中链生产停摆**，信号永远停在 watch_pending/buy_today，靠 stale 兜底。止损停摆 = 资金安全链失效。
- 修法：补 `run_monitor_safe = run_monitor`（或调度改调 `run_monitor`）；核查是否曾有安全包装被误删。

### L-2 🔴 startup 指纹未跟上「enabled/params 迁 yaml」：改策略宏开关/参数不再触发任何补偿
- `startup.py:263-283` 指纹 strategies 段仍从 config 读 `enabled`/`params`，而事实源已迁 `<key>.yaml`（`strategies/__init__.py:171-186`）⇒ 5 策略指纹恒 enabled=False、params={}；`strategies/*.yaml` 被归入 display 段（`startup.py:242-258`），改 yaml 只得 `display_changed` → "无需重建"（`startup.py:678-680`）。
- 后果：① yaml 里禁用策略 → `retire_unfilled` 补偿失效（2026-09-23 同类事故复发路径）；② 改 yaml params → 不触发重建校准，历史行参数口径分裂。
- 修法：指纹改读 `is_enabled`/`yaml_params`；含 meta.enabled/params/gates 的 yaml 划入 rules 段。

### L-3 🔴 break 出场三份实现、T+1 语义分歧，`exit_decision` 缺入场日守卫
- `break.py:626-643` `_decide()` 无 `held>1` 守卫（对比 `base.py:556-563` 明确加了并注释 T+1 约束）⇒ 入场日(D1)触止损/峰值逃顶即可出场 = **当日买当日卖**；
- `break.py:654-663` ①分支 `today_idx-1 >= entry_idx` 把 **D1 的止损触线**转成 D2 开盘强平，违反 R2 裁定「D2 起评 = D1 触线不产生出场」；
- `break.py:1244-1270` `_exit_by_decision` 从 d=1 起调 exit_decision，入场日可产 `exit_day=1` 当日平；
- `break.py:846-848` `_run_backtest_breakbuy` `if d > 1` 是正确口径 ⇒ 同一持仓三种结论。
- 影响：exit_decision 是折叠 replay + monitor 的**活路径**；golden 阈值口径不稳。修法：`_decide` 补 `held>1`、①分支排除入场日、`_exit_by_decision` 从 d=2 起。

### L-4 🔴 yaml `entry:`/`exit:` 块是惰性配置：改宏不生效，阈值双写
- `core/exit_modes.py:36 run_exit` 与 `core/entry_modes.py:56 resolve_entry` **全仓零调用点**（含 `StrategySpec.entry/exit` 加载后无消费者）⇒ 改 `exit.mode`/`entry.mode` **不改变任何行为**，违反目标态「所见即所得/改宏零改引擎」。
- 连带：`break.yaml:26-28`、`g56.yaml:36-38` 的 exit 阈值与 `params:` 段**双写**（现值一致靠人工纪律）；yaml 注释「由 exit.mode 分派读取」与事实不符。
- 注册的出场适配器（break_combo/combo/g56_no_trail/d1_open，约 120 行）全部不可达。修法：要么真正接 `run_exit` 分派，要么宣布 exit/entry 块为纯文档并删双写阈值。

### L-5 🔴 双开关矛盾：`scan_writer="scan_day"` 旁路折叠主线，Record 断流
- 行源由 `scan_writer` 决定（`scan.py:508`，config 现值 `"scan_day"`）；切片唯一生产入口 `present_daily.persist_days` 只被 `record` writer 调用（`scan.py:732`）⇒ **scan_day 下切片从不推进**。
- 而 `monitor_progress.enabled=true`（`monitor.py:331-386`）读同一份切片 → progress 恒空 → 四判定点恒回退旧三决策（安全但空转）；`startup._rebuild_worker` → `rebuild.projection_ledger_refresh` 读切片失败（`rebuild.py:973-975` "切片无投影"）→ `_RebuildIncomplete` → **指纹永不推进，每次重启重复失败**。
- `config.json` 的 `present_persist._note`（"已切 Record 投影"）与 `scan_writer` 现值自相矛盾。修法：scan_day 同步推切片或切回 record writer；收敛两开关语义。

### L-6 🟠 未来函数/求值异常被降级为「门未过」，不 fail-fast
- `core/runtime/evaluate.py:54-72` `_gate_error`：`AsOfViolation`（真未来函数！）仅 WARNING + 门按未过；其余异常首条 WARNING 后转 DEBUG；`:250/324/350/374` 四处 `except Exception` 静默丢信号。回测里脏表达式静默持续，与「静默降级是头号敌人」红线冲突。
- 修法：AsOfViolation 至少计数 + 阈值报警；表达式错误首次即报。

### L-7 🟠 重放/投影写库仍会用判定列覆盖操作列
- `rebuild.py:774-795` keep_marked 只保护 `exit_reason` 非空行、keep_actual 只保护「库有入场重放无入场」行；`rebuild.py:884-896` UPDATE 整列覆盖 `entry_price/stop_price/confirm_date` ⇒ monitor 按实价记的 entry_price 会被理论 D1 开盘价覆写。「操作事实不可重建」只做了一半。`vanish_settled` 仅报告不拦截。

### L-8 🟠 「数据尽头」两种结局 + exit_day 三套坐标
- 视野尽头未平仓：`core/exit_engines.py:364-371` **返回 None 丢交易** vs `core/replay/__init__.py:277-309` **造末日收盘平仓**——同一情形两条主路径结论相反，统计不可比。
- `exit_day` 含义：`exit_modes._d1_open:72-87` 卖在 entry_idx+1 报 exit_day=1；`trade_map.py:102` self-closed 恒 1；exit_engines 的 1 = 入场当日。canonical 字段口径不统一。
- `run_limit_seal:455-472`：D1 收盘卖出 = T+0，与 `_min_sell_day`（最早 d=2）矛盾（relay3 已退役但引擎仍活着）。

### L-9 🟠 run_trail_stop 触发判定仍用当日 high 抬线（日内先视）
- `core/exit_engines.py:263-266` 进循环先 `peak=max(peak, bar.high)`；`:314-323` 用抬高后的线判 `low<=trig` ⇒ 日线上无法分辨 high/low 先后，触发偏早。`use_trig_prev` 守卫只修成交价不修触发判定，与模块头注释（"防日内先视"）不符。分钟腿 `exec.replay_sell_intraday` 是正确口径（peak 逐槽推进）——两腿不一致。

### L-10 🟠 run_hold_stop 到期顺延 off-by-one，与 run_trail_stop 的缺陷互相抵消
- `core/exit_engines.py:156-169`：到期日一字跌停顺延后 `nxt = entry_idx + exit_d + 1` 跳过一个交易日且 exit_day 多 1（d 口径下顺延起点应为 `entry_idx+hold_days`）。
- `run_trail_stop:343-348` 持仓到期写入**无 `d==hold_days` 守卫也无 break**，exit_d 恰停在 hold_days-1，同型公式"碰巧"对——**修其中一处就会把另一处的 off-by-one 显形**。g56（hold_days=7）在到期日恰一字跌停时触发。

### L-11 🟠 upsert「先 DELETE 后 INSERT」：部分失败 = 信号蒸发
