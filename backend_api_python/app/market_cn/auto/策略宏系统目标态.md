# 策略宏系统目标态

> 维护：AI（方案设计文档，非代码）
> 原则：只写「目标态」，不写历史、不写兼容、不写修改记录。
> 一句话起点：**CSV 数据已定，宏（策略规则）是唯一要改的东西，引擎是读宏出结果的稳定工具。**

---

## 1. 心智模型

| Excel | 本系统 |
|---|---|
| CSV 原始数据 | 数据层（bars / 快照，滑动窗口 + 断点续传切片） |
| 函数 / 宏文件 | **策略宏**（规则，唯一人工 + AI 协作面） |
| Excel.exe | 引擎（回测 / 调试 / 展示 / 实时 = 同一条主干） |
| 计算出的工作表 | 落盘的信号与交易结果（四视图各自渲染） |

三条导出规则：

1. **策略只决定「规则是什么」**，不关心「规则怎么被执行」。
2. **所有视图只读宏**，不读宏的内部实现。
3. **改宏零改引擎；改引擎零改宏。**

**所见即所得**：修改宏文件，结果与展示立即跟着变。没有第二份规则要同步。

---

## 2. 分层与单一事实源

```
数据层（已定，不可变）  ──喂数据──►  引擎层（四视图一条主干）
宏层（唯一事实源）      ──读规则──►  引擎层
```

- **单一事实源 = 宏**。规则只有一份，存在策略宏里；回测、调试、展示、实时都读这一份。
- **所见即所得**：改宏，四处结果同时变，越简单越好。

## 3. 策略宏规范

### 3.1 宏的组成（两个文件，各司其职）

| 文件 | 装什么 | 不装什么 |
|---|---|---|
| `<key>.yaml` | **规则**：门表 + 参数 + 入场/出场 + 信号字段 + 开关 | 计算代码、历史注释 |
| `<key>.py` | **feat 原语**（规则引用的计算函数）+ 编排注册 | 规则判定本身 |

一句话：**yaml 决定「怎么判定」，.py 提供「判定用到的词」**。改规则改 yaml；加新词汇才碰 .py。

### 3.2 门表 schema

```yaml
meta:    name / market / version / enabled(true|false)
         enumeration(limit_up|day|intraday) / day_flow / day_start / day_end / ext
entry:   mode(next_open|open) / price / gap_max
exit:    mode(combo|break_combo|g56_no_trail|...) / 阈值(stop_loss/trail/hold_days...)
params:  可调参数（表达式里直接当变量引用；分板块用 {board: 值}）
gates:   [ {id, name, role: qualify|required, needs_d0: 0|1, enabled: 0|1, expr} ]
signal:  fields: { 字段名: {expr, fmt: none|r1..r6|int} }
```

- `role`：`qualify` = 与涨停日无关的资格门（每决策日算一次）；`required` = 依赖涨停日的判定门。
- `needs_d0`：该门是否读 D0 当日数据 —— 决定「T-1 夜能否预计算」，是展示提速的声明。

### 3.3 表达式 DSL 契约

门表 `expr` 是**受控表达式**，不是 Python：

- **只允许**：`and/or/not`、四则与幂、比较、函数调用、变量、常量。
- **三禁**：禁任意语句 / import / IO / 循环；禁属性访问 / 下标 / 跨股票引用；禁关键字参数。
- **偏移纪律**：`chg(-1)` 表前一日，**正偏移 = 未来函数**，加载期静态报出 + 运行期兜底，双重拒绝。

这套白名单把「未来函数」从「靠实测抓」变成「可证明不存在」——这是宏能安全交给 AI 改的前提。

### 3.4 feat 原语契约（三层，引擎统一绑定）

| 层 | 谁提供 | 例子 | 铁律 |
|---|---|---|---|
| 内置指标 | 引擎（稳定） | `close()/ma()/rsi()/macd_hist()/boll_*()/atr()/chg(k)` | 只读 ≤ 决策日 |
| 策略私有 | 各 `<key>.py` | g56 的 `feat()/warmup()/finite()` | 按策略隔离，同名互不可见 |
| 共享函数 | 引擎标准库 | `pk()/no_lu_last()/board_height()` | 单一实现 |

铁律：**纯函数无副作用**、**as-of 只读 ≤ 决策日**、**同名按策略隔离**。加新词汇 = 加一个 `fn(ctx, …)`，不改引擎。

### 3.5 开关（enable）

- **策略级** `meta.enabled: false` → 该宏**下线**：不展示、不生产。
  - 但**回测 / 调试仍可跑**（引擎照常加载、照常求值，只是结果不进展示与生产）。
- **门级** `gates[].enabled: 0` → 关掉某一道门，不删除它（想恢复翻回 1 即可）。

开关是「所见即所得」的一部分：关一个宏，只改一行，处处立即停。

### 3.6 该多薄（验收）

| 对象 | 目标态 |
|---|---|
| `.yaml` | 只留当前生效规则，无任何日期 / 历史 / 墓碑 |
| `.py` | 只留 feat 原语 + 编排注册，docstring 只写「这函数算什么」一句 |
| 整体 | 一个策略的规则，新人 10 分钟读懂并改对 |

## 4. 一条主干（回测 / 调试 / 展示 / 实时）

### 4.1 主干是什么

**主干 = 逐天复现引擎**。它做且只做一件事：

> 读一份宏 + 读一份数据，对每个 `(策略, 股票, 决策日 D)` 逐天推进：
> **求门 → 判定 → 出信号 → 持仓状态推进**。

主干逐天推进时，产出唯一一份中间产物 —— **事件流**（每票每天一条状态事件）：

```
ready   D 日门全过，出信号
exec    信号入场（next_open 次日开盘 / open 当日收盘）
exit    持仓到出场条件满足，平仓
```

**事件流是唯一事实**。回测、调试、展示、实时**不各自再跑一遍判定**，而是读这一份事件流、各自投影。

### 4.2 四视图 = 事件流的四种投影

| 视图 | 读事件流的什么 | 产出 |
|---|---|---|
| 回测 | exec + exit 配对 | trades → 胜率 / 盈亏比 |
| 调试 | 单天事件 + 每道门过 / 不过 | 「为什么出 / 为什么没出」 |
| 展示 | 事件流本身（ready / exec / exit 序列） | 信号 / 持仓 / 事件呈现 |
| 实时 | 当日事件 + 盘中快照帧 | 当日信号 / 盘中状态 |

四视图只差两样：**数据来源**（历史日线 / 分钟快照 / 当日断点）、**收集器**（配对成交易 / 记门原因 / 直接呈现 / 当日）。判定引擎只有一个。

### 4.3 展示层 = 主干的一个视图

展示层消费事件流，渲染信号 / 持仓 / 事件序列。它真正的价值在**呈现**，判定来自主干：

- **呈现样式**（信号列表 / 持仓状态 / 事件时间轴）—— 展示层自己的事；
- **数据切片**（滑动窗口 + 断点续传）—— 主干的数据来源，四视图共用。

展示层不是另一套判定引擎；它的信号 / 持仓 / 事件，就是主干那一份事件流的呈现。

### 4.4 盘中（intraday）也是主干

knife / tail 的分钟快照帧，是主干的**盘中数据分支**：同一份宏、同一套门求值，只是数据来源是分钟快照而非日线。它和日线策略是同一条主干上的两种数据来源，不是两条引擎。

### 4.5 复现任意一天（调试友好能力，非硬性验收）

给定 `(策略, 股票, 日期 D)`，能**完整重放 D 当天的判定**，且与当天生产结果逐位一致。
这是「有助于调试」的能力，**不做硬性门槛** —— 前提是不给系统引入速度 / 存储瓶颈。

四个支柱：

1. **确定性（纯函数）**：门表表达式是纯函数，同一份 `(数据 as-of D, 宏)` 必然算出同一判定。这是「可复现」的数学根基。
2. **断点定位（as-of 切片）**：任意 D = 把数据切成「末根 == D」的快照（数据层滑动窗口已定，这一步天然很快）。
3. **状态重建（成本权衡点）**：有状态策略（横截面池 / 滑动窗口）要复现 D，两种取法 —— 默认「重算重建」（从窗口头重算到 D，简单、慢、可接受）；「快照加速」（存中间状态）是**可选优化，不是必须**。不为秒级复现引入大状态缓存 / 大索引。
4. **门原因**：复现时顺带记「每道门过 / 不过」，调试直接回答「为什么没出 / 为什么出了」。

> 回测 = 逐天复现的连跑；调试 = 单天复现的放大镜。两者是同一能力的两种用法，不是两套引擎。
> 速度不是本能力的第一诉求：能复现、能逐门看原因即可，不必为「秒级」加码。

## 5. 迭代闭环（唯一人工 + AI 协作面）

```
改宏（门表 / 参数 / feat 原语）
   └─► 回测（读宏 + 历史数据，出交易）
         └─► 看结果（胜率 / 盈亏比；不对 → 复现那天 → 逐门看为什么）
               └─► 再改宏
```

只有这一步是人工 + AI 反复做的；数据、引擎、视图都是稳定工具。

---

## 6. 验收标准

1. **改宏零改引擎**：加策略 / 改规则 / 开关，引擎一行不动。
2. **所见即所得**：改宏，回测 / 调试 / 展示 / 实时同时变。
3. **单一事实源**：规则只有一份，不存在「改一边要同步另一边」。
4. **文件该多薄**：策略文件瘦到「规则 + 最小原语」，无历史、无兼容、无修改记录。
5. **下线即关**：`enable=false` 一行，不展示、不生产，回测调试照常。
