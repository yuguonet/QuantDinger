## 1. 系统全景

### 1.1 心智模型

系统 = **宏(规则)+ 引擎(读宏出结果)+ 数据层**。四视图(回测 / 调试 / 展示 / 实时)是同一判定主干的四种投影,差别只在**数据来源**与**收集器**:

| 层 | 载体 | 说明 |
|---|---|---|
| 数据层 | `core/data/`(hub 唯一 IO 出口) | bars / 快照 / 分钟;滑动窗口 + as-of 切片 |
| 宏层 | `strategies/<key>.yaml`(规则)+ `<key>.py`(feat 原语) | **规则唯一事实源** |
| 引擎层 | fold 折叠内核(`core/present/runner`)+ 回放(`core/replay`)+ 门表运行时(`core/runtime`) | 判定推进与收集 |
| 视图 | 回测 trades / 调试轨迹 / 展示 Record / 实时 progress | 各自投影,不各自判定 |

### 1.2 四视图现状

| 视图 | 入口 | 判定引擎 | 产出 |
|---|---|---|---|
| **回测** | `strategy_cli.py run` → `core/backtest.run_all` → `core.replay`(`backtest_stock` 薄壳) | 折叠 fold(stateful) | trades → 胜率/盈亏比 |
| **调试** | `tools/why·debug·replay·chat_why` | 门表 `evaluate_gates` / replay + TraceCollector | 逐门原因、逐笔明细 |
| **展示** | `present_daily.persist_days` → StateStore 切片 → `store` 投影 → `api.py` | 折叠 fold(stateless 补齐 ready) | 信号/持仓/事件序列 |
| **实时** | `monitor.run_monitor`(60s tick)+ `core/present/realtime.RealtimeBranch` | 当日切片 progress(可回退旧三决策) | 当日信号/盘中状态 |

### 1.3 一张图

```
物理源 (Postgres/上游): kline_1D · kline_1m · realtime_snapshot · dragon_tiger_store · stock_basic_info
        │
        ▼
core/data/hub.py ── 唯一数据出口(as_of 贯通,策略禁直连物理源)
        │
        ├────────────► strategies/<key>.py + <key>.yaml(宏:规则 + feat 原语)
        │                       │
        ▼                       ▼
┌─ 判定主干 ────────────────────────────────────────────┐
│ fold 折叠内核 (core/present/runner): init_state→evaluate→step │
│   ├─ 展示/实时: StateStore 切片 (Record: state/current/events) │
│   └─ 回测/调试: core/replay (DailyFeed/IntradayFeed + collectors) │
│ 门表运行时 (core/runtime): expr DSL → GateEvaluator → scan_day  │
└───────────────┬───────────────────────────────────────┘
                ▼
scan.py(盘后/盘中窗口)→ store.py: qd_dragon_signals(唯一事实表)
monitor.py(盘中状态机,60s)↗        │
                ├─ qd_watchlist 投影 + label 层
                ▼
api.py(只读 3 路由)→ 前端
```

**三处汇聚**:1 hub(数据只在此出一次);2 fold/门表(判定只在此算一次);3 store(落库只在此写一次)。

## 3. 策略规范:一个策略 = 宏(yaml + py)

### 3.1 两文件分工

| 文件 | 装什么 | 不装什么 |
|---|---|---|
| `<key>.yaml` | **规则**:meta(含开关)+ entry/exit + params + 门表 + signal 字段 | 计算代码 |
| `<key>.py` | **feat 原语**(门表引用的计算函数)+ 编排注册 + 折叠契约实现 | 规则判定本身(⚠ 现状仍含回测/调试残段,见问题清单 A-1) |

### 3.2 yaml schema(实测字段)

```yaml
meta:    name / market / version / enabled        # enabled = 策略开关唯一事实源
         enumeration(limit_up|day|intraday) / day_flow / day_start / day_end / day_min_n / ext
exit:    mode(combo|break_combo|g56_no_trail|d1_open|v1_combo)  # 只声明 mode,阈值一律在 params;见 3.6
         （✅ 2026-10-12 裁决 D1/D2，偏离已销账：`entry:` 收敛为**极小 schema**——
           入场**判定归门表 `gates`**，`entry:` 块只装「成交方式 + 过滤参数」；依赖累积
           状态的入场规则（break 断板 / knife·tail 窗口）继续留在 `.py`。
           v1.yaml 的 entry 死块（8 行）+ exit 阈值死块（3 行）已清理；
           设计基准《策略宏系统目标态.md》§3.2.1/§3.2.2 已同步反哺。
           ✅ `v1.py` DEFAULT_PARAMS 的 `require_d1_close_up` 死参数亦已删（零读取）。）
entry:   mode(close|next_open|intraday_window) / price(close|open) / gap_min / gap_max
         （✅ 2026-10-12 D2 接线完成: StrategySpec.entry 加载 + 三消费端
           —— entry_is_at_close() 覆盖类属性 / entry_fill_price() 驱动 exec 入场价 /
           entry_gap_ok() 通用 gap 过滤(monitor + fold exec)。
           当前各宏尚未写 entry: 块（调用方走类属性/缺省行为）；需要时才写入，**写即生效**。）
params:  可调参数(参数单一事实源;表达式中直接当变量引用)
gates:   [ {id, name, role: qualify|required|audit, needs_d0: 0|1, enabled: 0|1, expr} ]
signal:  fields: { 字段名: {expr, fmt: none|r1..r6|int} }   # 展示字段唯一事实源
```

### 3.3 门表 DSL 契约

- **允许**:`and/or/not`、四则与幂、比较、函数调用、变量、常量、字符串参数。
- **禁止**:任意语句 / import / IO / 循环;属性访问 / 下标 / 跨股票引用;关键字参数。
- **偏移纪律**:`chg(-1)` = 前一日;**正偏移 = 未来函数**,`expr.static_asof_check` 加载期拒绝 + `Ctx._check_k` 运行期拒绝(双重保险)。
- **偏移函数集**:`core/runtime/functions.py: OFFSET_FUNCS`。

### 3.4 feat 原语三层(引擎统一绑定)

| 层 | 落点 | 例子 |
|---|---|---|
| 内核原语(24 个,恒绑定) | `core/runtime/functions.py: Ctx` | `chg/k/vol_ratio/lu_close/pullback_days/monotonic_down/is_limit_up/count_limit_up/ma/rsi/macd_*/kdj_*/boll_*/atr` |
| 共享门函数(11 个) | `core/runtime/gate_stdlib.py` | `obv_rising/no_lu_last/macd_hist_lt/boll_bw_ok/board_height/ma_bull/is_bse/ret_n/d1_vol_ratio/is_approx_limit_up/pk` |
| 策略私有门 | `strategies/<key>.py` 模块级 `register_strategy_funcs("<yaml-stem>", {...})` | break: feat/turnover_sig/bkf/entry_*;dragon: gap_days/dragon/streak/...14 个;g56: feat/finite/warmup/pool_*;knife: feat/ok/hhmm/mkt_gain;tail: feat/hhmm/limit_hit/ok/nf/v2/pred_* |

- **key 隔离**:`STRATEGY_GATE_FUNCS` 按 YAML stem 组装(`build_funcs(ctx, key, names)`),同名互不可见。
- **D0 依赖**:`D0_DEPS/REGISTERED_D0` 声明门是否读决策日(⚠ 夜算管线已退役,声明当前无消费,见问题清单 D-5)。

### 3.5 策略插件契约(`strategies/base.py`)

**必选**:`key` / `name`;`scan_signals(bars, code, *, as_of, ctx, **params) -> list[Signal]`;折叠契约三件套 `init_state(code, bars)` / `step(state, bar)` / `evaluate(state, inp, prev) -> [Progress]`。

### 5.3 分钟数据纪律

- **分层取数**:`minute_composite.hybrid_series`(近端 `DEFAULT_MINUTE_DAYS`≈100 交易日走 1m,远端 1D,互斥不丢日);**禁止整窗 1m**。

3. **快照按年分表且可能丢拍** → 跨年/对账显式处理;缺拍只标注(展示无回溯性)。
