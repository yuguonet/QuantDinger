## 一、已确认问题

> 以下证据与描述记录修复前状态；各项当前状态见「六、修复记录」。

### F-01 🟠 G56 空共享状态恢复时未清空旧台账

- **位置**：`strategies/g56.py:336-339`，`G56Strategy.init_shared()`
- **证据**：恢复逻辑仅在 `shared` 为真时创建 `PoolLedger`。当持久化状态为 `{}`（例如文件没有 `meta`），当前实例已有的 `ledger` 不会被重置。
- **复现**：给实例预置含 `2026-10-12` 记录的台账，再调用 `init_shared({})`，旧记录仍可从 `ledger.window("main")` 读出。
- **影响**：跨日横截面池统计可能混入持久化状态中不存在的旧数据，进而影响 G56 的 regime / 分位判定。
- **建议处理**：每次都按传入状态重建台账；空共享状态应等价于空台账，而不是“沿用实例状态”。
- **建议回归**：覆盖非空台账恢复 `{}` 后清空；覆盖非空快照恢复；覆盖连续重复恢复的幂等性。

### F-02 🟠 滑动缓存将复权因子读取异常伪装成指纹 `0`

- **位置**：`core/data/window_cache.py:95-124`，`_factor_fp()`
- **证据**：快路径不可用后会调用 `fetch_qfq_factors()`；该调用抛异常时函数返回 `0`。本轮注入 provider 异常，确认实际返回 `0`。这与函数注释“不因拿不到指纹返回恒定值”的承诺相反。
- **影响路径**：缓存原指纹也是 `0` 时，真实复权因子已变化但因子读取暂时失败，比较仍得到“未变化”；该股票不会进入全量重取列表，旧 qfq 历史可能继续被当作有效缓存返回。指纹原值非 `0` 时通常会触发重取，风险主要集中在“旧指纹为 0”的场景。
- **建议处理**：区分“确实无因子”和“因子读取失败”，读取失败不得作为 `0` 参与相等比较或写入缓存；应显式失败/令缓存不可用并走安全回退。
- **建议回归**：旧缓存指纹为 `0`、因子读取抛错时，不得命中旧缓存为有效结果，也不得把错误状态写成新指纹；因子正常变更仍须触发整票重取。
- **关联**：旧审计清单 `系统审计问题清单_20261009.md` §1 L-16 已记录此风险，本轮重新核实仍存在。

### F-03 🟠 M1 影子对拍缺少两份必需基线

- **位置**：`tests/present/test_m1_sampler.py:216`；缺少 `tests/golden/baselines/break_real_000032.json` 与 `tests/golden/baselines/dragon_crafted.json`
- **证据**：展示层测试实际运行时，上述两个参数化用例均因 `FileNotFoundError` 失败；检查工作树确认两个文件都不存在。
- **影响**：`tests/present` 不能全绿，M1 影子路径对拍无法执行。设计文档中“10/10 Golden 基线已入库”的概述不足以覆盖这两个 M1 用例依赖的文件。
- **建议处理**：将对应、可复现的基线纳入版本库，或把测试改为使用现有权威 fixture；不要静默跳过对拍。
- **验收**：缺失基线在干净 checkout 中也可运行 `tests/present/test_m1_sampler.py` 对应两例。

## 二、潜在风险（当前活跃策略宏未使用）

### R-01 ⚪ DSL 除零返回 `0.0`，可能让错误数据通过门

- **位置**：`core/runtime/expr.py:158-162`
- **证据**：除法和取模的右操作数为零时返回 `0.0`，不是报错；本轮确认 `evaluate("1 / 0", {}, {}) == 0.0`。
- **影响**：如果未来门表达式使用除法/取模构造比率，分母异常可能被转换为普通数值，并在 `<`、`<=` 等比较中误通过。
- **现状边界**：检查现有 `strategies/*.yaml` 后，没有发现实际使用 `/` 运算的活跃门表达式，因此暂列潜在风险，不作为当前线上策略已受影响的缺陷。
- **建议处理**：在 DSL 中明确除零语义；优先抛 `ExprError`，由门求值层记录错误并拒绝该门。增加除法和取模除零测试。
