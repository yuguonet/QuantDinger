## 2. #3 的"偏离"值得单独说：这是**好偏离**

方案 #3 的修法（去掉 `nxt` 的 +1）建立在审计 B3-2「两引擎缺陷互相抵消」的诊断上。执行方构造实测推翻了它：

- `run_trail_stop` 的 `+1` 与它循环内 `pending_dn` 分支的 `d` 自增语义配套，**全部场景自洽**（实测三场景一致）；
- `run_hold_stop` 在「到期日封跌停」场景确实输出错（`exit_day=2/price=10.0`，提前平仓），但成因是 **`exit_d` 赋值点结构**（跌停分支只置 `pending_dn` 不记 `exit_d` ⇒ 尾块起点退化），不是 `+1`；且实测证明"只补 `exit_d=d`"仍不对（`exit_day=5/price=7.0`）——**不是一处最小修**。

⇒ 执行方选择**锁现状 + 标注 known_anomaly + 留专项**，而不是照方案硬修。这符合判定原则 P2（唯一实现只做收敛）与"不矫枉过正"。**我方审计 B3-2 的根因诊断应视为已被证伪一半**（缺陷存在、机理说错）；`test_exit_rollover_real_behavior.py` 是新的事实基准。

⚠️ 但注意：`run_hold_stop` 到期日封跌停的**输出错误仍在生产**（g56 在用该引擎），专项应排期。

  与 `monitor._now_hm()` 改成**显式绑定 `TZ_CN`（北京时间）**，与 realtime_snapshot
  写入端（realtime_snapshot.py:55）同口径，不再依赖宿主时区。当前 docker(Asia/Shanghai)
