- **方式**: ① 静态走线(逐交接点核对谁写谁读、键对不对得上)② 可执行模拟
  (纯函数层真跑,合成数据,零外部依赖;脚本 `.openclaw/tmp/sim_dataflow.py`,24 项全过)

## 一、数据流全景(模拟走线)

```
用户输入
 → bridge.resolve(entity→域倒推/clarify 短路)          [域通道②:实体→域]
 → _prefetch(记忆/RAG/金例注入, 报告落 trace)          [金例数字不进 grounding 语料 ✓]
 → _maybe_preselect_tools(闸门→词典→plan→lint→激活)   [域通道①:数据域词典]
 → ReAct(每轮工具面;fail-open;预算熔断)             [weight_hints 只提示 ✓]
 → grounding gate(只认 role=tool 语料 ✓) → _plan_lint
 → _intake_accountability → record_decision            [域通道③:追责域闸门]
      └─ classify_domain → intake_gate → extract_claims → decisions/claims
 → _c3p_pipeline → extract_evidence(LLM) → aggregate(coefs=None) → record_pair(JSONL)
 → _record_case(EV-1 载荷, label=pending)
盘后: evaluator → resolve_due_claims(交易日历取价✓) → resolutions
      → weight_feed(每 claim 一票✓, domain 聚合✓) → qd_agent_weights
      → weight_hints(TTL) → 回到预选提示/技能排序                    [闭环✓]
      → collector(context_frame + daily_universe)                    [⚠ 只写不读]
P3 缺口: calibration.fit_with_pooling ← pairs                       [孤岛, β 无生产者]
```

**模拟确认健康的 8 个点**: R1 双道拦截、Δlogit 裁剪留痕、fail-open 退回 p_base、
n<30 不出 β₀、池化如实标注(n=5/pooled_n=45/source=parent,不冒充)、τ 过期留档、
每 claim 一票去重、delisted 单列不进胜率。

## 二、发现的问题(9 项,S 系列)

### S-1【高】视界抽取"首个命中"⇒ 显式窗口被口语词压掉(实测复现)
合成回答"短线看多,T+3 目标价 1900"——`guess_horizon` 的 `_HORIZON_RULES` 把
"短线/短期"→T+1 排在 "T\+?3"→T+3 **之前**,首个命中即返回 ⇒ claim horizon=T+1,
而分析者明示的是 T+3。**标签窗口与声明窗口错位**(T+1 与 T+3 方向可能相反),
直接污染 T+N 判定与下游校准。
**修法**: 两遍扫描——显式窗口(`T\+\d`/`N 个交易日`)优先于口语词;显式无命中才用口语词。
落点 `chain/claims.py::guess_horizon`。

### S-2【高】多 claim 证据串标(c3p.run_for_decision)
`extract_evidence` 只抽 **works[0]** 的证据,随后 `for cid, c, code in works` 循环里
**同一个 ev** 挂到每个 claim 的 pair 上(aggregate(pb, ev, ck))。多标的回答(一问两股)
时,claim#2 的 pair 带着 claim#1 的判别特征/证伪条件;`extra.subject` 记的却是各 claim
自己的 code ⇒ **错配被静默掩盖**。当前 coefs=None 无症状;P3 后会把 A 票证据算进 B 票 Δp。
**修法**: 逐 claim 抽证据(多一次轻量 LLM,或仅 works[0] 走证据、其余 pair 标
`ev_missing` 不吃经验加成);至少在 pair 里记 `ev_subject` 强制可对账。

### S-3【高】§19.1 降级门未落进流程(实测演示)
设计红线:"缺证伪条件 ⇒ 本次预测降级,**p_final = p_base**(不给经验加成)"。
现状:`degraded` 只是 extra 里的 flag,`aggregate` 照常跑——模拟里 ev=None +
coefs={"b0":0.25} 得 p_final=0.61 ≠ p_base,**降级样本照样吃经验加成**。
当前 coefs=None 恰好掩盖;P3 接线时若只传系数不补门,校准样本立刻被污染。
**修法**: `run_for_decision` 里 degraded ⇒ 强制 pf=pb(或 aggregate 增加 degraded 入参);
这是 **P3 接线的前置门**,必须先于 β 拟合。

### S-4【中高】案例延迟回填挂在"待退役"的旧链路上
`backfill_by_root` 唯一调用点在 `chain/store.py`(写 `qd_agent_traces` 验证结果那段)。
O-2 退役 traces 评估链路时,金例的 pending→correct/incorrect 回填会**静默断**
⇒ 案例永远 pending、永久 0.5× 降权、few-shot 金例永不"转正"。
**修法**: O-2 立项时把回填调用迁到 `resolver.resolve_due_claims` 之后(与 resolutions 同源)。

### S-5【中】采样→分析→案例产线缺环: daily_universe 只写不读
`sampler.pick_daily_universe` 每日落 150 只,`collector.load_universe` **零消费方**。
统计功效的地基(150 只/日 ⇒ 361 独立簇/年 ⇒ MDE 7.4pp)建立在"采样标的被分析成案例"上,
而案例目前只来自用户请求(量级远小)⇒ **MDE 表的前提当前不成立**。
**修法**: 拍板二选一——① 接"采样→批量自动分析→claim"产线(run_skill 批量/盘前任务);
② 承认案例靠用户积累,回收 MDE 口径、按实际速率重算功效预算(§10 反推条件格数)。

### S-6【中】pair 记录缺 y/证据字段 ⇒ P3 拟合要三店 JOIN
`record_pair` 落 as_of/claim_id/p_base/p_final/delta_p/ck/extra;**没有 verdict(y)、
没有 discriminators**。拟合 β₀ 需 pair×resolutions(PG)×evidence(JSONL)按 claim_id 三方 JOIN。
O-4(exp_pair 表)/O-5(经验存储合一)不做,校准数据工程脆弱但可跑;若做,顺手把 y/ev 键并进。
**修法**: P3 最小路径 = 写一个 `calibration.build_cells()` 明确承担该 JOIN(单一口径),
不要散在拟合脚本里。

### S-7【中】聚合器证据项是 count-based 一阶近似,与设计公式不一致
§15.1 设计 `Σ βⱼ·eⱼ`(逐判别特征系数);实现是 `_coef(coefs,"discriminators") * len(disc)`
(按**条数**计一次系数)。calibration 只出 b0 ⇒ disc/fals 系数**无生产者**,
逐键 βⱼ 依赖 §18 判别特征挖掘(未开工)。两实现自洽,但设计文档与代码口径需二选一对齐
(建议:§15.1 加"v1 为 count-based 一阶近似,逐键 βⱼ 待 §18 挖掘后升级")。

### S-8【低】degrade_reason 恒空
`extra={"degraded": degraded, "degrade_reason": ("" if degraded else "")}` —— 三元写反,
degrade_reason 恒 ""。应为 `"" if not degraded else "no_falsifiers"` 之类稳定标签。

### S-9【低】两个口径注意(非 bug)
① `due_date_of` 取 max(精确交易日, 自然日估算)是"宁可晚判"的有意保守——
T+1 claim 实际判在 +3 自然日后,与 D3 双窗口"T+1 快速出结论"的意图有偏差,注意别误读成慢。
② `grounding_failed` 的结论照常进追责(可辩护:更该追),但 decisions 不记 status
⇒ "溯源失败的结论是否更不准"无从分析,建议 intake 落库时带上 run status。

## 三、处置顺序建议(喂给 P3 方案)

| 顺序 | 项 | 理由 |
|---|---|---|
| **P3 前必修** | S-3(降级门)、S-1(视界口径) | 直接决定校准样本的标签质量;都是 ≤20 行 |
| **P3 方案内建** | S-2(逐 claim 证据)、S-6(build_cells 单一 JOIN 口径) | 决定 β 拟合输入的正确性 |
| 与 P3 并行 | S-4(回填迁点,挂在 O-2 上)、S-5(产线拍板) | 不阻塞 β,但决定样本量级 |
| 记账 | S-7(文档对齐)、S-8、S-9 | 便宜 |

**与前几轮结论的关系**: S-3 与"问责/经验同源污染"分析中的护栏 2(degraded 不吃加成)
是同一件事;S-5 印证了"独立簇预算"讨论——没有采样产线,12 格预算要按真实案例速率重算。

### 补记:S-3 的**另一侧(拟合侧)** —— 同一轮补齐(增量追加 · AI · 2026-10-14)

上面只装了 c3p 侧(推理时"这次吃不吃加成")。复核发现**另一侧没落**:
`calib_feed.build_samples` **不滤 `extra.degraded`** ⇒ 降级样本会进拟合、去决定
**给别人**的 β₀。已补齐,两侧现在是同一条纪律:

| 侧 | 落点 | 行为 |
|---|---|---|
| 推理侧 | `chain/c3p.py::run_for_decision` | `degraded` ⇒ **根本不进经验环节**(不是"算了再压回去"):不调 `aggregate`,`p_final = p_base`;且**留痕同步**为 `calib_source="degraded"` / `calib.used=False` —— 否则会出现「source=cell 但 Δp=0」的矛盾行(把没用的当成用了 = 静默放大) |
| 拟合侧 | `chain/calib_feed.py::build_samples` | `extra.degraded` 的 pair **不进样本**;口径走 **`QD_CALIB_EXCLUDE_DEGRADED`**(默认 1 = 滤),不硬编码 |

⚠ **留了可回滚的口子(反直觉,务必知道)**:降级样本的 `p_final` 恒 = `p_base`
⇒ 它们是**不含自我修正**的最干净样本,而 β₀ 的 estimand 正是「实际胜率 − p_base 均值」。
⇒ 若日后格子因样本量迟迟达不到 30 簇,把开关置 0 让降级样本回流即可,**不必改代码**。

**验证**:新增 4 条(拟合侧门 + 2 条反向/env 开关 + 留痕一致性),共 **22 条**;
变异检验 **4/4 有 bite**(M1 视界 / M2 推理侧门 / M3 拟合侧门 / M4 留痕同步)。
回归 **765 passed / 4 skipped**(761 + 4),smoke **255/257 · 0 failed**。

(`pairs=2`、`resolutions=0`,库连通但判定表空)⇒ 补门正是时候(样本还没开始攒)。
