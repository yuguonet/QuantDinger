## 0. 一句话结论

> 让系统靠数据沉积自我校准，**方向可行，但必须换目标、换数据源、换顺序**：
> 目标从「提升预测力」降到「校准该信几分」；数据源从 agent 问答换成回测引擎先验 + agent 残差；
> 顺序从「先改 agent」换成「先做回测侧」。

## 1. 六项提智能力现状盘点

对照通用 agent 提智清单（性价比从高到低）核查 `app/agent` 现状：

| # | 条目 | 完成度 | 结论 |
|---|---|---|---|
| 1 | 结构化 Prompt + Few-Shot | 🟨 结构化 90% / Few-Shot 30% | Prompt 工程成熟；few-shot 基础设施建好但**没接线** |
| 2 | 工具增强（计算器/检索/代码） | ✅ 95% | 六项中最高，是系统核心投入方向 |
| 3 | Self-Reflection | 🟨 50% | 有 grounding gate 单维反射，无通用自省闭环（有意决策） |
| 4 | 上下文压缩 + 外挂记忆 | ✅ 80% | 双通道在线，缺会话跨进程持久化 |
| 5 | 多次采样 + 验证器 | ⬜ 在线 10% / 离线 70% | 在线零采样；但 T+N 真值验证器是独特资产 |
| 6 | SFT 微调 | ⬜ 5%（仅数据地基） | 未做；追责四表已是天然高质量标注数据源 |

### 1.1 关键发现

**① few-shot 链路「建好了、电没通」**
`utils/case_memory.py`（506 行）实现了完整的 run 级 few-shot 机制（T+N 延迟标签回填、incorrect 硬排除、pending 降权），但全仓核查：`record_case()` 与 `format_case_injection()` **0 处调用**。唯一活通道是 `search_knowledge` 工具 → `retrieve_cases`（需模型主动调）。

**② 疑似半死代码**
`tools/returns_sampler.py` / `returns_contract.py` 自述接线点为 `nodes.py` / `agents/task_agent.py`——**这两个文件已随旧编排层删除**，v2 代码中无任何调用方。建议确认后接回或归档 `del/`。

**③ 在线多次采样为零，但这是合理路线选择**
`constants.py:44` 的 `AGENT_PLAN_BEST_OF_N` 仅是 env 声明残留，全仓无实现。系统把算力投到了 `chain/resolver.py` 的 T+N 真值判定 + `chain/weight_feed.py` 的 EMA 权重反哺——**用真实世界结果当验证器**，比当轮采样投票更贴合金融场景。

**④ 第 5 项在本场景下大部分是浪费**
有真值就不需要多候选投票。防线应从「验证结论真伪」缩减为「防逃逸 + 防归因」。

### 1.2 改进建议（按性价比排序）

| 优先级 | 建议 | 依据 |
|---|---|---|
| **P0** | 接线 case_memory：`record_case` 挂 `_finish_collector` 后置、`format_case_injection` 挂 `_prefetch`（受 `CASE_MEMORY_ENABLED` 保护） | 机制已写完，纯接线活，性价比全场最高 |
| **P0** | 确认 returns_sampler/returns_contract 死活，接回或归档 | 429+ 行疑似死代码留在工具扫描目录是隐患 |
| **P1** | 先做改进路线 C（能力评测 benchmark） | E/F/G/K 四项与将来 SFT 的共同前置，官方路线已标 P0 |
| **P1** | Self-Reflection 补「对题性」轻校验，复用 grounding 重试位 | 沿用已验证的独立预算重试机制，成本可控 |
| **P2** | 开 `QD_CLAIM_JUDGE` 前先建人工校准集（`judge_stats` 已给出 >20% 分歧率判据） | 做强已有离线验证器，比在线多采样更贴合本系统哲学 |
| **P3** | 在线多次采样**不建议做**（与省 token 核心约束冲突）；SFT 等 C 落地 + resolutions 攒到千级再评估 | 路线 L 存档判断同样适用 |

## 2. A 股专项缺口

### 2.1 会污染追责闭环的三条口径缺陷（最高优先级）

| # | 缺陷 | 证据位置 | 后果 |
|---|---|---|---|
| **1** | **涨跌停/停牌无可成交性过滤** | `chain/resolver.py:158-168` `verdict_by_rule` 只判方向，方向对即 `hit 0.75`；`evaluator.py:183` 只处理「退市/停牌取不到行情」的跳过 | 推荐一字板/涨停票 → 事后判「方向对了」→ 虚高胜率 → `weight_feed` EMA 学到「涨停票该推」的伪规律 |
| **2** | **收益判定未扣交易成本** | 同上，`_FLAT_PCT = 0.3`（±0.3% 判横盘） | 单边印花税 0.05% + 双边佣金 + 滑点，往返约 0.1~0.3%，**与判平阈值同量级**。小资金 T+1~T+5 策略边际收益被成本吃光 |
| **3** | **纯绝对收益判定，无相对基准** | `verdict_by_rule` 只比个股自身涨跌 | A 股 beta 极大，指数普涨日方向对 ≠ 有 alpha。牛市权重全体虚高，熊市全体误杀 |

**建议**：
- claims 提取时附带标的当日**可成交标志**（涨停/一字/停牌），resolver 出 `unrealizable` verdict，与 `undecidable`/`data_missing` 同处理、**不计入权重**（已有该语义，加一类即可）
- `fetch_actual` 收益减成本模型（印花税+佣金+滑点，走 env 配置），或至少把 `_FLAT_PCT` 抬到成本之上 + buffer
- 增加**并行指标** `excess_return`（减沪深300/中证500/中证1000 按市值分档基准）。绝对 verdict 答「能不能用」，超额答「有没有 alpha」

### 2.2 工具面偏食

核查 `tools/finance` 全部 69 个公开函数：技术面/资金面/情绪面/榜单极强（龙虎榜、涨停池、筹码分布、限售解禁、多空研判），但**财报与估值维度近乎空白**（仅 `batch_valuation_compare` 一个）。

1. **财报/业绩预告工具**，必须带**公告日期**字段——`kline_tools.daily` 已有 `as_of`、`fund_flow` 返回体已带 `as_of`，财报类必须延续：**用公告日期而非报告期**，否则整条链都是前视偏差
2. **ST / 退市风险指标**（营收<1亿且亏损等财务类退市）。当前 agent 完全无此感知
3. **复权口径显式化**：`utils/grounding.py:135` 记录了「复权同值不同号」的坑，但那是在匹配层擦屁股。更彻底做法是工具返回体带 `adjust` 字段

### 2.3 时段与实时性

- `domain_registry.py:45` 的 `trading_calendar` 默认 `False`——**先确认 finance SPEC 是否打开**。9:15-9:25 集合竞价挂单可撤（虚假量）、14:57-15:00 尾盘集合竞价、11:30-13:00 午休。建议注入「当前交易阶段」
- 数据延迟标注：`fund_flow` 已带 `as_of` 是好样板，应推到所有行情类工具

### 2.4 Prompt 与记忆层 A 股化

- **few-shot 金例先建 taxonomy**（趁 case_memory 接线一起定）：诊个股 / 选股 / 板块复盘 / 大盘研判 / 交易确认 / 止损复核六类
- **标的有效性校验**补进 grounding：6 位代码 + 板块归属校验（60/000/300/688/8/4）、退市股过滤、简称歧义澄清
- **合规词表**（`grounding.py:70` 已有「必然涨停」「保证收益」）补 A 股高频违规口径：禁承诺保本、禁「内幕/庄家拉升」式表述

## 3. 自校准闭环的分层设计

核心原则：**越往下越「可写」，也越危险**。

| 层 | 内容 | 权限 | 说明 |
|---|---|---|---|
| **L0 事实层** | 工具输出、行情数据 | **只读** | 由数据源保证 |
| **L1 执行层** | traces（root/skill/tool 三层树） | **只读** | 记录发生了什么 |
| **L2 判定层** | claims / resolutions | **只读** | 由代码算真值，**不接受解释** |
| **L3 归因层** | 为什么错 | 受控写入 | 需受控枚举 + 客观锚点 |
| **L4 因果层** | 改了之后变好没 | 需验证 | 需分组对照 |

> L0–L2 必须只读。`claims`/`resolutions` 之所以值钱，恰恰因为它由代码算真值、不接受解释。**一旦允许上层反向改写下层，闭环就废了。**

### 3.1 归因不能信（最大的坑）

「agent 自己找原因」这一步，LLM 几乎**总能**给出听起来合理的解释。解释的生成成本太低、验证成本太高。项目原则「可回测 > 可解释 > 可复现」正好命中：解释是最廉价的那一档。

**两条硬规则**：

1. **归因必须落在受控枚举上**，不接受自由文本作为动作依据。金融域初始枚举（写进 yaml，符合「规则不在代码里」）：
   `工具缺失 / 工具误选 / 数据口径错 / 时限不当（horizon 错配）/ 市场环境误判 / 纪律违反 / 判定阈值失当 / 真随机`
   每条归因必须带**客观锚点**（哪个 trace 节点、哪条 claim、哪次工具调用）。无锚点的归因**只记录、不触发动作**
2. **动作必须 out-of-sample 复核才固化**。触发分析用的样本窗与验证窗必须分开——同一批样本既发现问题又证明修好了，就是自动过拟合

### 3.2 校准旋钮清单（金融域）

| 旋钮 | 现状 | 校准难度 |
|---|---|---|
| 工具预选面 | `tool_preselect` + `preselect_stats` 已留观测口 | 低，有客观命中率 |
| 技能选择与注入量 | `weight_hints` 只做 tie-break | 低 |
| 阈值参数（`_FLAT_PCT`、相似度、注入阈值） | 多为拍脑袋初值 | 中，需扫描 |
| prompt 纪律条目（`qd_system.txt`） | 有 `qd_prompt_eval` 回归套件 | 中，改前必须过套件 |
| SKILL.md 正文 | `skill_brewer` 有 revise + `.bak` 轮转 + `human-edited` 保护 | 高，不可逆性强 |

**粒度**：先做 `domain × regime × 任务类型` 三维，**不要一上来做因子级**。

**A 股强要求（不能省）**：必须按 **regime 分桶**（牛/震荡/熊 × 量能 × 题材活跃度）。break/dragon/g56/knife/tail 全是短线情绪型策略，同一套参数在不同 regime 下表现完全相反；**不分桶校准出来的值，是把不同市场状态平均掉的噪音，比不校准更糟**。另外**有效样本数要按题材/标的去重折算**——一个窗口里同题材那批票反复出现，名义 200 条，有效可能只有 20 条。

### 3.3 保存：把「每次分析」当实验档案

- `qd_calib_runs` — 一次后台分析一行：触发条件、样本切片指纹、用了哪些证据、结论摘要
- `qd_calib_hypotheses` — 可证伪假设：**判据**（哪个指标变多少算成立）+ 预期方向 + 复核窗口
- `qd_calib_actions` — 旋钮 old→new，状态机 `proposed → applied → validated / reverted`

**关键**：证据包存 **id 引用，不存内容拷贝**。存 200 条 resolution 的内容会因口径变更而漂移，存 id 列表 + 当时切片指纹即可重放。

### 3.4 可直接复用的现成资产

- **后台子 agent 分发**：`run_skill` → 子进程 `scripts/skill_run.py`（超时可击杀、崩溃隔离、主上下文只拿摘要）。加一个 `calib_analyze` 执行型技能即可，不需要新机制
- **触发点**：`evaluator` 盘后 worker 已有，但分析按样本阈值触发更省
- **延迟标签语义**：`case_memory.backfill_by_root` 的 T+N 回填正是校准动作所需——动作效果也得等复核窗
- **两个现成闸门**：`qd_prompt_eval`（改 prompt 必过）+ `skill_brewer` 的 `.bak` 轮转与 `human-edited` 保护

## 4. 真值能覆盖什么，覆盖不到什么

### 4.1 覆盖得到的（结论层无法说谎）

`direction` / `magnitude` / `level` 三类 claim 都有 T+N 真值锚点，说错了就是错了。**这意味着第 5 项「多次采样 + 验证器」大部分是浪费**——别人没有真值才需要投票，真值免费且验证强度远高于任何当轮验证器。

**防线从「验证结论真伪」缩减为「防逃逸 + 防归因」，复杂度降一大截。**

### 4.2 覆盖不到的（五类盲区，每类都能在代码里找到实名入口）

| # | 盲区 | 机制 | 说明 |
|---|---|---|---|
| **①** | **可证伪性逃逸** | `intake_gate` 的「宁漏不脏」会静默排除模糊表述 | 说「可能上涨，注意风险」→ 抽不出 claim → 不入闸、不算失败。设计本身正确，但**制度化地给了模糊表述免罚通道** |
| **①b** | **评分套利** | `verdict_by_rule` 横盘 `partial 0.5`，方向反才 `miss 0.2` | 「不确定时说可能横盘」的期望收益 > 「明确看错」。真值不会说它错，但**它在退化** |
| **②** | **cherry-picking** | grounding gate 保证「每个数字可溯源」 | 但保证不了**没有故意漏掉反面证据**。看多时只调资金流龙虎榜、不调估值财报——每个数都是真的，整体结论是偏的 |
| **③** | **归因** | 无 | 「我错是因为没看资金流」没有任何真值能验证。这是 L3 必须受控枚举的原因 |
| **④** | **因果** | 无 | 改了 Y 之后变好 ≠ 因为 Y。真值只验证结果变好，验证不了因果成立 |
| **⑤** | **保守化退化** | 无 | 若校准让 agent 越来越只说有把握的话，命中率一路上升、权重一路上升，**真值全程绿灯**，但系统在变成不敢说话的废物。唯一「每个单项都对、整体在变差」的失效模式 |

### 4.3 对策：不看单条，看统计指纹

这类「合法说谎」逐条防不住，但都有群体统计特征：

| 指标 | 定义 | 异常信号 |
|---|---|---|
| **可证伪率** | claims 数 / 有实质结论的答复数 | 下降 = 在变滑头 |
| **undecidable 占比** | 判定为不可判定的 claim 比例 | 上升 = 在变滑头 |
| **出声率** | 给出明确结论的答复占比 | 下降 = 保守化退化 |
| **反向证据率** | 给出方向性结论时，是否调用了至少一个反向口径工具 | 下降 = cherry-picking |

前两个直接补在已有 `preselect_stats`/`judge_stats` 那套「只观测不改行为」的计数器里即可——**设施已经在了**。

**因果类用分组对照做反事实验证**：若归因 X 为真，则 X 类样本失败率应显著下降，**而其他类不应变化**。若全体一起变好，多半是市场变好了，不是改对了。成本几乎为零，能挡掉大部分「运气当能力」。

> **一句话**：真值核对是**阅卷**——能判答案对错，判不了「为什么错」和「为什么不答」。
> L0–L2 不用再加固，已是正确的。真正需要设计的只有 L3（归因）和 L4（因果），
> 而这两层的防线是**受控枚举 + 统计指纹 + 分组对照**，比多采样验证器便宜得多。

## 5. 数据沉积：三层结构

### 5.1 硬阻塞（最重要发现）

**个股级沉积当前数据模型不支持。**

`chain/weight_feed.py` 模块头明文：

> resolutions 挂 claim → decision，decision 只带 domain/intent，**不带 tool/skill 归因**。
> domain 是这张表能诚实支撑的最细粒度。

即 **`decisions` 表连 `symbol` 字段都没有**。1 万条攒完后切不出个股维度，也切不出题材维度。

**这不是算法问题，是加三个字段的事**：`symbol` / `theme` / `regime`，claim 抽取时填上。成本极低，**但必须现在做**——等数据攒完再补，前面的一万条全都没有这三个维度。

### 5.2 有效样本 ≠ 名义样本

A 股样本**高度不独立**：同题材、同一天的 20 只票同涨同跌，名义 20 条，信息量约等于 1 条。

| 粒度 | 有效样本 |
|---|---|
| 名义问答条数 | 10,000 |
| 去同期相关 · 题材×日期聚类折算 | ≈ 3,000 |
| 按 regime 分档（3 档） | ≈ 1,000 / 档 |
| 再按任务类型（6 类） | ≈ 170 / 格 |
| 下钻到个股（5000+ 只） | **≈ 2 条 / 票** |

若这 1 万条是 3 个月攒的，只覆盖 1 个 regime，学出来的是「这 3 个月怎么玩」。

**建议：先做「策略 × regime × 任务类型」级，个股级等跨过 2 个 regime 再开。**

### 5.3 三层结构 + 层级回退

```
L1 原始层 · 不可变
    问答 / claims / resolutions，只追加不改写，可重放
        ↓
L2 聚合层 · 条件频率表
    domain × regime × 任务类型 × horizon → 胜率与分位
        ↓                    ↑ 样本不足回退
L3 实体层 · 个股 / 题材档案
    带时间衰减，A股半衰期建议 60–120 交易日
```

**层级回退（shrinkage）**——唯一能让个股级在只有 2 条样本时也不闯祸的办法：

```
w = (n · p_个股 + k · p_父层) / (n + k)，k ≈ 20–30
```

小样本向父分布收缩，样本够了自动松绑。

### 5.4 沉积是放大器，不是纠偏器

若采集本身有偏（只在对的票上出结论、行情好时才答、保守化），1 万条只是**把偏差固化一万次，还给它披上「数据支持」的外衣**。必须先有代表性监测（可证伪率 / 出声率 / 题材覆盖度 / regime 覆盖度），再谈沉积。

**与现有代码直接冲突的点**：`case_memory` 的 `incorrect` 硬排除，对 few-shot 注入是对的（别拿错例当示范），但对统计沉积是**反的**——1 万条里最值钱的是错的那 3 千条。**这两条通道必须分开设计，不能共用一套过滤。**

## 6. 可行性第一性评估（核心）

### 6.1 目标必须拆分：A 可行，B 不可行

| | A · 校准 | B · 提升预测力 |
|---|---|---|
| 问的是 | 该不该信自己、信到几分 | 更会预测涨跌 |
| 可行性 | ✅ **可行** | ❌ **基本不可行** |

B 不可行的理由很硬：个股日频收益的可预测成分极低。业界天花板（几千因子、PB 级数据、专业团队）样本外 **R² 仅 1%–5%**。用 1 万条 LLM 非结构化样本去提升——差 **2–3 个数量级**，不是努力能补的。

A 可行，因为校准**不需要预测能力**，只需要历史命中率。

> **结论：把目标从 B 降到 A，可行性从「不可能」变成「能做」。**

### 6.2 真正的可行性杀手不是样本量，是 X 不稳定

统计学习要求输入特征 X 在样本间**同构**。但 agent 问答的 X 是：问法千差万别、每次调的工具不同、路径不同、结论语义每次略有漂移——**X 空间开放且非平稳**，直接 pooled 估计在统计上不成立。

**唯一解：投影层。** 把每次问答**确定性**投影到封闭、可枚举的特征向量上，且**必须由代码做，不能由 LLM 做**（LLM 做的会漂）。

建议维度：

- 父层级：板块 / 题材 / 市值档 / 流动性档（**注意不是 symbol 本身**，5000 个不能直接编码）
- regime：量能 / 情绪 / 波动率 / 指数趋势（代码算）
- claim 类型：direction / magnitude / level（已有）
- 结论强度 score（已有）
- horizon：T+1 / T+5 / T+20（已有）
- 依据口径：技术 / 资金 / 基本面 / 情绪 / 消息（可枚举，关键维度）

> **投影层是整个方案成立的枢纽。** 有它，1 万条才变成一张规整的表；没它，1 万条只是一堆文本。
> 而它当前在系统里不存在——`decisions` 只有 domain/intent。

### 6.3 数据源选错了：应该用回测引擎当先验

QuantDinger 的主业是回测引擎——`break`/`dragon`/`g56`/`knife`/`tail` 五策略，全市场、全历史、逐日跑（canonical 产物含 `d0_date`/`exit_reason`）。那才是**百万级、结构化、point-in-time、可任意回溯**的样本。

**agent 的 1 万条问答，在回答「什么有效」这个问题时，是噪声级数据源。**

正确分工：

| | 回答什么 | 数据规模 | 可靠性 |
|---|---|---|---|
| **回测引擎** | 什么有效 | 百万级 | 高 |
| **agent 沉积** | 何时说 / 说多重 | 千级 | 需先验兜底 |

于是 agent 不用学「这类票会不会涨」（回测已知，百万级），只需学**「我在回测已知胜率之上，是系统性偏乐观还是偏悲观」**——这是**残差学习**，样本需求从万级降到百级。

**收益**：可行性大幅提升，且**今天就能启动**，不需要等 1 万条攒完。

### 6.4 三个不随架构消失的硬约束

| 约束 | 现实 | 后果 |
|---|---|---|
| **反馈周期** | 改一个旋钮 → 攒够新样本 → 验证，一轮 2–3 个月 | 一年只能跑 4–6 轮。每轮必须只调一点点，且**并行试多个假设**，不能串行 |
| **非平稳** | A 股个股特性半衰期 3–6 个月 | **只沉积「股性」，不沉积「方向」** |
| **标签口径** | 涨跌停不可成交、未扣成本、无相对基准 | 不修这三条，沉积的是脏标签的精确平均值。**前置项，非可选项** |

**关于「只沉积股性」**：波动弹性、板块跟随度、消息敏感度、涨跌停惯性、流动性特征——这些相对稳定、可验证、确实有用；而「这只票上涨概率 62%」这类不该沉积，它下个季度就废了。

## 7. 分期实施建议

### 一期（可行，6–8 周见效）

- **目标**：校准，明确不做预测提升
- **核心构件**：投影层（确定性、代码做）→ 条件频率表 → shrinkage 回退
- **粒度**：regime × 板块/题材 × claim 类型，**不到个股**
- **先验来源**：回测引擎
- **作用点**：**行为旋钮**（工具预选、是否发声、技能排序），**不是置信度显示**
  - 理由：若结论生成过程不变，只把结论乘一个校准系数，收益有限——只是更准确地知道自己在瞎猜。真正有价值的是改变行为
- **验证**：前后对照 + 同期基准（金融无真 A/B，只能如此）

### 二期（现在不具备条件）

- 个股股性档案
- **前置**：跨 2 个 regime 的样本 + 投影层跑稳半年 + 标签口径修完

### 顺序建议（强烈）

**先做回测侧沉积，别先动 agent。**

1. 回测侧立刻可行：样本无限、结构化、不依赖任何 agent 改造、能马上验证
2. agent 侧必须等投影层定义稳定才有意义——**投影层一旦改，之前沉积的坐标全废**。顺序反了会白干
3. **附带收益**：回测侧先跑起来会**反过来告诉投影层该有哪些维度**（哪些切分维度在百万级样本上区分度显著），比拍脑袋定维度可靠得多
