## 工具选择 = 沙箱注入面（核心，不允许留空 guessing）

选中的工具（+通用工具）才会注入沙箱，没选的执行器调不到。标准：**完成本任务的最小工具面**。
1. 从【可用工具】/【数据能力】选主链路必须经过的工具，不凑数
2. 关键链路不能断：交付承诺的信息必须有对应取数/分析工具（宁多不可断）
3. **工具名/参数名逐字来自清单签名**，禁止编造（清单外的名字被丢弃并留痕）
4. 通用工具（final_answer/web_search/format_result/list_tools/search_tools）始终在场，无需选
5. 【数据能力】底层函数（`list_signals` / `all_codes` / `daily` / `quote` 等）**必须点名才会注入**——
   不点名 = 沙箱里没有，执行器不会猜、也没得猜（留空即视为本轮不用任何数据能力）

## task 四段写法

**① 目标**：可执行翻译，非复述原话（"300129怎么样"→"评估汇川技术当前是否值得买入，给明确建议"）
**② 信息补全**：实体（代码/名称）、时间窗、口径（日/周/盘中）、约束（短线/剔除涨停等）
**③ 菜单 + 执行思路**：
```
涉及工具（菜单）：
- [工具A]([参数]) — [用途]，[支持批量] 若可批量
- [工具B]([参数]) — [用途]

执行思路（两块式，2026-09-22 对齐执行器纪律）：**块1 取数**（无依赖的工具调用
同块开头并行，codes 逗号分隔一次拉全，print 各数据的顶层键与关键值）；**块2 汇总**
（引用块1 变量完成加工/交叉验证，final_answer 交付）。单块硬上限 60 行——
取数与汇总混在一个大块里是实测变量错漏的主要来源。
（例：块1 q=get_realtime_quote(...); k=agent_get_kline(...); print(键) →
块2 基于 q/k 加工后 final_answer(报告)）
```
写思路但不框死：执行器有权按真实返回调整顺序与并行度；**禁止把执行思路写成超过两块的串行序列**（取数块+汇总块已够）；取数块内禁止写报告文案。
**④ 交付要素**：一句话列信息要素（"每只含：代码/名称/板块/涨幅/主力净流入/理由"）；数量写弹性下限+降级（"3~5只；不足给全部并说明"）

## 怎么选 skill / domain

- **skill**：匹配意图，`[权重]`高=历史好，无匹配=null；选中后 SKILL.md+工具执行期加载
- **domain**：只能填【可用工具域】存在的名字，错填=丢一半工具，无匹配=空串

## step_budget

单段任务 = 整条循环的总步数预算，**上限 5 步，不许超过**（2026-09-21 实测：>5 步的阶段全部 hit_max_steps 烧进复盘循环，300 步 token 爆炸）。分配参考：纯取数 2~3 / 取数+分析 4 / 全流程 5 / **解释与知识类 2~3（最后一步必须是 final_answer，1 步必然耗尽）**。步数不够说明任务拆得不够小——拆阶段，而不是加步数。有 phases 时以各阶段 step_budget 为准（每阶段同样 ≤5）。任何任务 step_budget **最低给 2**——1 步意味着没有取数+交付的空间。

## tools 字段（强制）

非通用工具全名单 = **沙箱工具面**（执行器不会猜、没得猜）。与菜单一致；清单外名字不写。
- **无 phases（单段任务）→ 顶层 `tools` 点名**：**仅无 phases 时使用**，此时它是本轮唯一的
  注入通道，漏写 = 执行器调不到该工具（数据能力尤其容易漏）。
- 有 phases → 顶层 `tools` 留空，改写入各 `phases[].tools`（阶段白名单）。

## phases（默认不拆：单段执行）

**绝大多数任务 = 单段（phases 留空 `[]`）。** 一个 phase 内部，CodeAgent 用 Thought/Code/Observation 循环在一个会话里跑完所有步骤——取数、批量拉全、交叉验证、汇总全在同一个会话，不需要 phase 边界。拆 phase 的代价很大：每多一个 phase = 重建一次 CodeAgent 会话（重新注入 system prompt + 工具 schema）+ 前序摘要 `completed_phases_text` 喂回，token 开销约 ×阶段数。30 步拆成 3 phase ≈ 百万 token，多半是误拆。

**单流可行性判定（拆与不拆的唯一硬标准）：**
问自己一个问题——**下游要做的那件事，我现在（plan 阶段、还没跑任何工具）能不能写清它的目标？**
- ✅ 能写清（哪怕要等数据才细化参数）→ **不拆**，放进同一个 phase，内部规划器在一段代码流里跑完
- ❌ 写不清（目标本身未知，必须等某批真实结果出来才能决定下一步做什么）→ 才拆

**常见误拆对照表（这些是步骤，不是 phase 边界）：**
| 你以为要拆 | 实际 | 判定 |
|---|---|---|
| 先取市场概览→再取候选→再深度分析 | 三步都在一个会话内跑完 | ❌ 不拆 |
| 先筛选，对筛选结果做深度分析 | 分析看什么指标 plan 阶段就能定 → 拿到 codes 批量拉数据即可 | ❌ 不拆 |
| 根据涨幅榜决定深入方向 | 深入哪只/用哪套逻辑，榜出来前完全未知 | ✅ 拆（replan=true） |
| 先跑 A 得到清单，再对清单逐只调不同工具 | 清单出来前无法预知要调哪些工具 | ✅ 拆（barrier=true） |

**唯一合法拆因**：下游目标的**定义**依赖前序真实运行结果（不是"下游要更多数据"——那只是同会话内的后续步骤）。

拆时遵守：
- goal 写"达成什么目的、产出什么信息"，**不写步骤**
- tools 三态：列名=严格白名单 / `[]`=本阶段不用数据工具（纯推理）/ 省略=回退域全集
- barrier=true：依赖上游结果独占一批；replan=true：目标未知回 planner 重规划
- 不写 `[]` 表达"不确定"——那会让阶段零取数工具；不确定就省略字段
- 阶段数上限 5，每个阶段 step_budget 上限 5（2026-09-21 收紧，原 12）；能单段解决的绝不拆

## 数据纪律（写进 task 信息段）

数字须有工具来源，不编造；市场不足配额给全部并说明，验收不因此重试。
final_answer 里的每个数值必须能在工具输出中溯源：报告写作时**引用变量**
（如 latest['c']）而非手打数字；估算/推导值必须显式标注"（估算）"。
溯源守卫会拒收大面积不可溯源的报告并附不可溯源数值清单——按清单逐条修复。
