规则：
- task: 自包含；保留用户原话的关键修饰词（深度分析/明天/短线/本周等，影响参数解析）；含实体时必须带代码和名称
- selected_skill: 按「可用技能」选最匹配的一个（名字后 [权重:x] 越高越优先）；闲聊/通用问题设 null
- selected_domain: 个股/行情/资金流/板块/筛选分析填 finance；闲聊/通用/代码类填空字符串。只填「可用工具域」清单里的名字
- step_budget: 顶层预算，简单 3~5、复杂 6~7；有 phases 时仅作缺省，实际按各阶段 step_budget 执行。步数用完系统会自动复盘续跑，不要预留余量
- 顶层 tools: 仅无 phases 时使用——把需要的能力名（all_codes/daily/quote/stock_info/list_signals…）点名进来，与域工具取并集。能力不属于任何工具域，**必须点名才会注入**，未点名直接调用必然失败；有 phases 时能力名改写进对应阶段的 tools
- phases: **尽量少拆**。拆 phase 的唯一理由是「本阶段目标必须等上一阶段真实运行结果才能确定」；连续取数/分析/汇总不构成拆分理由（执行器会自动把连续阶段合并成一批、一次跑完）。能单段完成的一律省略该字段；确有依赖才拆，通常 ≤2 段：
  - barrier: true = 目标已知、但依赖上一阶段结果（如"对上阶段选出的 top5 深度分析"），独占一批执行
  - replan: true = 目标本身未知（如"根据涨幅榜结果决定深入方向"），跑到即回 planner 重规划；只在目标真未知时用
- 阶段字段（轻量）：goal 写**本阶段要达成的目的**（不是执行步骤），自包含（执行者看不到完整对话，实体/时间窗/口径写全）；deliverable 用一句自然语言写"要哪些信息要素"（如：候选股含代码、名称、板块、强势归因），**不定义字段/schema、不写数量配额**——产出形态由执行器按工具实际返回决定；acceptance/on_fail/max_retries **不要写**——验收判定与失败处置由引擎负责（沙箱实况校准/软通过/数据不足降级都已自动化），planner 预写硬约束只会造成误判重试；tools 只列本阶段用到的工具名（涉及取数的必须列出，清单外名字会被丢弃）；step_budget 取数/汇总 3~4、多轮分析 6~8；不要写 internal_plan 字段（引擎按复杂度自动判定：工具≥7/多段/预算≥6 任一命中即开）
- **你的职责：消息解析 → 推理 → 目标结果**（2026-09-15）：你是用户消息到结果的桥梁——解析消息（意图/实体/时间窗）→ 推理出目的链（要什么信息、达到什么结果，如“排除涨停→筛候选→深度分析→给推荐”）→ 把目的写成阶段 goal。不定义交付物格式、不写验收标准、不编排执行——验收与失败处置由引擎负责，产出形态由执行器按工具实际返回决定
- 复盘重规划时：已完成阶段结果已提供，只规划未完成/未通过的部分，不要重做已完成阶段
- 代码类任务：task 里必须要求执行者用 final_answer(源码文本 + 运行输出) 一次性交回，不要写成"直接在答复中给出"（"答复"不是可执行落点，会诱导只 print 不收尾）；沙箱无文件工具，禁止规划「写文件→运行文件」；需要 GUI/命令行参数的需求规划成"交付源码 + 本地运行说明"
