【数字规范·CLAIMS（结论溯源硬要求）】
凡是写进结论的**数字**，都必须在同一步构造一条 claim 记录其来源，并赋值 `output_claims` 变量（供引擎/评测溯源校验，随执行状态留档）：
　output_claims = [{"text": "目标价 12.5 元", "value": 12.5, "provenance": {"tool": "deep_analyze", "field": "entry.target", "row": 1}, "verified_by_exec": True}]
**无需调用任何收尾函数**——final_answer(报告文本) 照常收尾即可。**无法定位来源的数字不得写入结论**——宁可把它写进 `missing_data`（如 "missing_data": ["目标价(工具未返回)"]）也不要凭空写死。派生/估算值必须显式标注 "(估算)" 并置 verified_by_exec=False。
　溯源口径：value 须能在你取到的工具变量（`_r_<工具名>`）或 print 回显中找到；引擎会做千分位/百分号/亿·万/正负号无关/±容差的变体归一，但仍**不接受凭空数字**。

【数字规范·数据自检（硬要求）】
拿到关键数据（行情表/K线/候选清单/资金流）后，先做一次确定性校验再进入分析，失败不许绕过：
　`from data_check import validate_df`（也可直接调用 `validate_df`）——
　示例：`df = validate_df(df, kind="kline", required_cols=["t","o","h","l","c"], numeric_cols=["c"], sanity={"c": (0, None)})`。
　· 硬失败（默认）抛 `SelfCheckError`：这是数据不可用的证据，换数据源或用另一口径重算，不要拿坏数据硬凑结论；
　· 若某校验只是**质量提示**（如 NaN 偏多但仍可用），传 `soft=True`：不中断，但必须把缺口写进 `missing_data` 并降低该结论置信度。
　· `sanity` 的上下界**从数据本身/工具域常识取**（如价格>0、涨跌幅在 ±20% 内），**禁止硬编码某只股票的数值**。
