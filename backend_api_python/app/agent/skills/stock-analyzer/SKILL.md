# 单只个股全周期多维诊断（stock-analyzer）

## 何时用 / 何时不用

| 用户问法 | 用哪个 |
|---|---|
| 分析一下 600519 / 茅台怎么样 / 这只票能拿多久 | **本技能** |
| 600519 该如何操作 / 是不是该割肉 / 跌破 70 怎么办 / 止损位设多少 | **本技能** |
| 600519 资金流入流出情况 / 还能不能拿 / 能不能回本 / 怎么进攻防守 | **本技能** |
| 今天买什么 / 有什么好股票 / 短线选什么 | `market-screener` |
| 茅台现在多少钱 / 今天涨了多少（只要一个价） | `auto-finance-query-stock` |

本技能**只诊断被点名的那一只**，不产出候选池、不做横向比较。用户一口气报多只时逐只调用。
判断口诀：只要问题里有**被点名的单只个股 + 走势/操作/止损/资金流/去留意图**，就用本技能；
只有纯报价、或多只横向选股时才让位给别的技能。不要在主流里对单只票逐个调
`get_realtime_quote`/`technical_analysis`/`get_fund_flow` 拼答案——那会绕过方向纪律并让
同一票不同时点结论漂移。

## 调用方式

```
run_skill("stock-analyzer", {"fn": "analyze", "kwargs": {"code": "600519"}})
```
`deep=true` 追加多周期结构与龙虎榜席位（更慢，默认不开）。多周期（`mtf`：日线 / 15m / 5m
的位置与强弱）是**独立证据维度，不参与七维投票**，只用于印证与精细化。其中
`weak_to_strong`/`strong_to_weak` 是**当日盘中换手**口径（VWAP 收复与否），
与日线 `regime` 的「弱转强/强转弱」（看跨日位置）**同名不同义**，不可互相替代或改写。
`mtf` 带 `caliber_check`（日线目标日 / 1m 最后一根日 / `aligned`）；`aligned=false` 时
`stale=true`，15m/5m 的 `close`/`trend`/RSI 属更早交易日，写作时**明确不采信、不得据此说
「短周期转暖」**，并在缺口中留痕；不删这些字段，只标口径。

证据基座是 **deep 层**（market-screener deep 装配层的独立演化副本，见 `_deep.py`）：`analyze()`
内部经 deep 装配单票全维证据（日线技术面 / 形态 / 资金 / 实时对账 / 封板 / 标定预测分），
在其上做多维投票、支撑压力交叉验证、板块涨跌修正，再给结论。
`analyze()` 返回的 `report_guide` 是本技能交付给调用方的报告写作契约；主对话应遵循该字段，
不需要在通用服务层识别个股任务或重复注入本技能规则。

## 交付形态：短、确定、不漂移

- `brief` 是三档 + 长档的一句话骨架，写作时**直接照它落笔**，不要重列完整表格；
  结论全文有字符上限（见 `report_guide.LENGTH`，`QD_STOCK_ANALYZER_REPORT_MAX_CHARS` 可调）。
- `horizons` 只输出 T+1/T+3/T+5 三档，每档一行「方向（置信度）｜触发｜证伪」；
  五档逐档计算仍在内部保留，T+10/T+20 由 `trend_outlook` 的日线趋势一句话承载，
  不逐档给触发/证伪/概率。
- 方向词只用词表五选一，禁「可能/建议关注/谨慎乐观/或有压力/大概率」等模糊措辞（见
  `report_guide.DIRECTION_WORDS`）。
- 同一只票对不上上一轮结论时：调用方可把上一轮三档结论作为 `prev_horizons`
  入参传入，`consistency` 会列出方向/止损的变化事实；写作必须按 `report_guide.CONSISTENCY`
  写明「由 X 改为 Y，依据 Z」，Z 只能是本轮新出现的可观测事实。没有新增事实时维持上一轮，
  **不得仅因时点变化（早盘→晚盘）翻转方向**。不传 `prev_horizons` 时不产出该字段。

## 方向词表（五选一，不要发明新词）

| 词 | 什么时候用 |
|---|---|
| **看多 / 看空** | ≥2 个证据维度同向、且与反向维度差值 ≥2（多证据互相印证） |
| **中性** | 多维均无方向信号且证据足（有效维 ≥3 且不少于未知维）——平衡是结论 |
| **证据不足** | 只有单一维度给方向、或多空并存差值 <2、或维度间无法相互验证 |
| **未知** | 关键数据缺失 / 日线不够长 / 价位推不出——**不知道就答未知** |

**语义边界（反复被踩，硬纪律）**：
- 证据不足 ≠ 看空，未知 ≠ 利空。它们都是「不下结论」，不是负面结论。
- 不猜测、不妄想：结论只允许来自返回的事实字段。缺数就承认缺数。
- 「中性」也是结论，同样要多维印证；拿不准就落「证据不足」。

## 全周期档位

| 周期 | 含义 | 能不能给概率 |
|---|---|---|
| T+1 | 次日 | **能**，用 `p_up`（唯一标定数字） |
| T+3 | 3 个交易日内 | 不能，只给方向 |
| T+5 | 1 周 | 不能 |
| T+10 | 2 周 | 不能 |
| T+20 | 1 个月（封顶） | 不能 |

天数取 `app.agent.chain.label_spec.HOLDS` 的**唯一真源**，本文不写具体天数；
封顶 T+20 ≈ 1M 是 2026-10-23 的用户裁定，不要自行外推到 T+30/T+60。
`horizons` 字段只输出 T+1/T+3/T+5 三档方向、触发与证伪；五档内部计算保留不删，
T+10/T+20 不做强调，只按 `trend_outlook` 的日线趋势简述（MA20/MA60 位置与 20/60 日区间），
不逐档给概率、触发条件与证伪条件。

## 多维投票（每档方向怎么来的）

每档由 7 个证据维度投票（+1 多 / −1 空 / 0 中性 / None 缺数）：

| 维 | 证据 | 备注 |
|---|---|---|
| model | P(T+1涨) 标定分 | **只投 T+1**，其余档不外推、不计入 |
| structure | 均线结构 / 20 日位置 / 乖离 / 贴支撑 | 结构维缺数 ⇒ 该档直接「未知」 |
| volume | 量比、对大盘校准 vr_rel、5 日量能趋势 | 涨无量（背离）是空证据 |
| flow | 5/20 日资金净额、对大盘 flow_rel | 口径=量价方向净额，**禁止写「主力」** |
| market | 相对上证超额 rs_d0 / rs_5d | 剔除大盘 β 后的强弱 |
| sector | 板块/概念 α（见下节） | 板块涨跌幅缺失 ⇒ 该维「未知」 |
| tape | K 线形态 / 封板结构 / 连板透支 / 拉高出货线索 / **解禁供给压力**（日历源） | 空形态列表=确实无形态，不是缺数 |

判定：同向 ≥2 且差值 ≥2 ⇒ 给方向；否则按上表落「证据不足 / 中性 / 未知」。
每档输出 `votes`（逐维票）与 `basis`（逐维依据），可复核、可推翻。

## 板块/概念涨跌幅修正（β/α 拆分）

当日涨跌拆成 **β（板块/概念带动）+ α（自身）**，α = 个股涨跌 − 板块基准
（行业板优先，缺则所属板块均值）：

- **自强**（α≥+1.5%）：跑赢板块，自身强势；α 本身是 sector 维的多证据；
- **跟板块**（其间）：涨跌含 β 成分，不算自身强弱；
- **自弱**（α≤−1.5%）：**上涨类证据作废**（放量上攻/突破形态等被修正掉并注明），
  个股 +2% 板块 +5% 不是强势；反过来下跌系板块带崩（α≥+1.5%）时
  **下跌类证据作废**——板块暴跌个股小跌可能是自强；
- 板块/概念涨跌幅取不到 ⇒ 该维答「未知」，**不猜 β、不做修正**，缺口留痕。

## 补充事实字段（描述性，不参与七维投票，不改变 confidence）

- `market_outlook`：底层已标定的**大盘次日涨概率** `p_up`。它是描述性事实，
  不外推到 T+3 及以后，也不充当个股方向票。
- `cap_regime`：按「大盘走弱且跌家数多涨家数少 ⇒ 大流通市值相对占优；
  大盘走强且涨多跌少 ⇒ 小盘相对占优」给出的市值分层事实（`favored` / `fit`）。
  市场宽度取 `realtime_snapshot` 横截面逐票涨跌家数（不是两大指数抽样）；
  流通股本缺数时 `float_mcap_yi` 为 None，不做硬筛。阈值见 `QD_STOCK_ANALYZER_*` 环境变量。
- `board_rank`：板块内排名、涨跌家数、涨停家数，以及 `role`（龙头 / 同板涨停 /
  跟风 / 反向 / 未跟随 / 无涨停龙头）。盘中与历史同源取 `realtime_snapshot` 分钟拍，
  **不用 `kline_1m`**（盘后回填、盘中当日为空，与快照净额差 55%~78%，不得拼接）。
- `trend_outlook`：T+10/T+20 的纯日线趋势，只描述 MA20/MA60 位置与 20/60 日区间。

以上四个字段只作事实陈述，与方向结论分开写；缺数答未知，不据此给买卖指令。

## 支撑 / 压力位（每侧 1-2 个，附推敲演算痕迹）

`levels` 用 **8 类独立方法**（均线 / 枢轴 / 波段 / 区间 / 缺口 / 密集区 / 涨停起点 /
关键位引擎）对候选价位 ±1% 聚类交叉验证：

- **verified=True**（≥2 类方法聚合或 30 日**有效测试** ≥2 次）才可当结论价位；
  有效测试 = 触碰且当日收回；**穿越不收回只计失守次数（broken）**，不撑验证强度；
- **verified=False 是孤证**：只可参考，引用时必须注明「孤证」；
- 每个价位带 `touches`（有效测试次数）、`broken`（失守次数）、`held_last`（最近一次
  测试守住与否）与 `verdict`（推敲结论）；`levels.checks` 是完整演算痕迹；
- 该侧推不出价位 ⇒ 答「未知」，**不编价位**。
- 触发/证伪条件锚定在这些价位上；长档（T+10/T+20）优先锚 ma20/ma60/lo60 级别。
- **止损两层**：`levels.nearest_support` 是距现价最近且 verified 的支撑（阈值
  `QD_STOCK_ANALYZER_STOP_NEAREST_MAX_PCT`，默认 6%）；短档（T+1/T+3/T+5）非看空方向的
  `invalidate` 优先锚它作**止损参考位**，方法数更多的远支撑放 `last_defense` 作**最后防线**，
  两者都写清；两层的距离差记在 `stop_pressure.gap_between_stops_pct`。不止损失一层吞掉另一层。

## 离场压力（`stop_pressure`）

`stop_pressure` 把已算出的负面事实按条数汇总（2026-11-26 口径）：收盘在日内低位（≤5% 分位）、
5 日资金净流出、弱于板块（α≤-阈值）、大盘情绪偏弱（≤`QD_STOCK_ANALYZER_WEAK_SCORE`，
与 cap_regime 同源）、两层止损距离、筹码套牢压顶、尾盘连续分钟净流出、情报一票否决、
融资余额回落、开盘区间向下破位、日内均线空头、日频资金连续净流出。它是**事实汇总，不是
买卖/仓位指令，也不改方向投票与置信度**；`n` 高时写作层前置「核对止损参考位」的提醒，
用户问去留/止损时据此展开，用户只问分析时按条件情景陈述。阈值来自既有字段口径，不新造维度。

## 事件与时段口径

- **事件（`events`）**：目前唯一有日历的事件源是限售解禁。窗口内有占比 ≥1% 的
  解禁 ⇒ tape 维的空证据（T+1/T+3 看 ≤20 日，其余档（含 T+5）看 ≤45 日）；30 日内解禁进 `risks`。
  日历取不到 ⇒ 该条**缺数**（None）并留痕，不猜。除权除息无日历工具，不做。
- **时段（`session`）**：`pre`（盘前）/ `intraday`（盘中）/ `post`（盘后）/
  `closed`（非交易日）/ `unknown`（交易日历不可用）。判据是**先判交易日、再判时刻**：
  非交易日恒 `closed`（数据为最近一个交易日收盘，触发条件落到下一交易日），
  日历不可用时 `unknown`（此时不要排条件单）。触发条件的时间口径随之变化
  （盘中=今日剩余时间，盘后/非交易日=下一交易日条件单，盘前=今日观察项）——
  不要拿盘中诊断当次日预案。注意午休 11:31~13:00 仍算 `intraday`（今日还有剩余
  交易时间），与「此刻能否拉到新报价」不是同一判据。

## 两个置信度字段（不要混为一谈）

- `evidence`：**证据完整度** = 拿到的维度数 / 计入维度数（rt/tech/prediction/
  patterns/flow/sector/zt）。它回答的是「数据齐不齐」，不是「我对不对」。
- `confidence`：**该周期方向的把握度** = 档位上限 × evidence × 一致度
  （|同向维−反向维|/有效维）。只有方向成立时一致度才非零。
  T+1 上限最高（有标定），越远的档位上限越低。

`confidence` 低 ≠ 看空。低只是说证据不足。`horizons[].agree` 是一致度原值。

## 每周期必须落到四要素（硬纪律）

**禁止**「可能上涨」「建议关注」「谨慎乐观」「或有压力」这类措辞——它们没有可执行信息。
每一档必须写全：

1. **方向**：看多 / 看空 / 中性 / 证据不足 / 未知（五选一）
2. **触发条件**：什么情况才算成立（如「回踩 ma10(12.30) 不破且量能转强」）
3. **证伪条件**：跌破/站上哪个价位就算判断错了
4. **关键价位**：从 `levels` 取（经验证的支撑/压力，注明是否孤证）

数据不足时写「证据不足」或「未知」并说明缺什么——**这比编一段更合格**。

## 可以推翻模型，但要写明依据

`horizons[].basis` 列出了各维证据。你不认同时必须写明理由，
且理由要落在可观测事实上（支撑是否守住、量能、资金方向、板块 α、20 日位置），
不能只说「我觉得」。支撑与结构的优先级 ≫ 涨跌幅。

## 阈值与环境变量（单源，2026-11-26 收敛）

- 七维投票与风险标记阈值集中在 `run.py` 的 `_VOTE_THRESHOLDS` 单源表（改值=改判定纪律，须回测复核）；
- `QD_STOCK_ANALYZER_ALPHA_PCT`：板块自强/自弱阈值（默认 1.5），label/证据修正/投票/离场压力四处同源；旧 `QD_STOCK_ANALYZER_STOP_WEAK_ALPHA_PCT` 停用；
- `QD_STOCK_ANALYZER_BARS_DAYS`：日线取数天数（默认 120），deep 与 analyze 同源生效；
- `QD_STOCK_ANALYZER_DEEP_BUDGET`：deep 满卡字符预算（默认 44500；原借用的 `QD_SCREENER_DEEP_BUDGET` 对本技能停用）；
- `QD_STOCK_ANALYZER_WEAK_SCORE` / `STRONG_SCORE`：大盘弱/强判定门（默认 45/55，cap_regime 与 stop_pressure 同源）；`_mood_label` 的 40/70 只是展示分桶。

## 失败模式（别踩）

- 把 `p_up` 外推成 T+5 / T+20 的胜率 —— 它只覆盖 T+1
- 把「证据不足 / 未知」当成看空信号 —— 它们只是不下结论
- 把低 `confidence` 当成风险信号 —— 风险看 `risks` 字段
- 把板块上涨当个股强势 —— 先看 α，自弱票的上涨证据已被修正掉
- 引用未验证（孤证）价位却不注明 —— `verified=False` 的价位必须带「孤证」字样
- 编造数值：工具没给出的数字不允许出现在结论里
- 用 VWAP / 分时均价当买点 —— 价位只用 `levels` 里经验证的支撑/压力

## 资金、事件与建议的证据边界（股票分析质量修复，2026-11-04）

- `flow` 是量价方向净额近似，不是按账户类别识别的真实资金流；不得称为「主力资金」、
  「机构资金」或据此断言主力进出。保留工具给出的估算/近似限定。
- 龙虎榜席位/机构明细只可归因于工具返回的 `detail_date`，且该日期必须与 `records`
  中的上榜日期一致。日期缺失、不一致、`records` 为空或明细有错误时，不要把汇总金额
  归到某个交易日，也不要将无日期的机构汇总写成当日资金信号。
- 报告区分「工具事实」「推导」和「判断」；每个外部事实保留来源名称、发布日期/交易日。
  搜索只用于工具数据缺失的关键事实：相同事实最多检索一次，整份报告最多 2 次检索；
  优先公告/交易所等一手来源。搜索结果的股票代码或名称不匹配、日期不明、仅有摘要且
  无可核验来源时，不把它当作事实；注明未能核实即可，不要重复搜索或补猜。
- 增持、回购等事件只陈述公告事实及其可能影响，不推断「托底」「保证支撑」等确定效果。
- 用户只说「分析/怎么看」时，给方向、证据、风险和条件，不给命令式买卖/仓位指令。
  只有用户明确询问操作建议时才讨论情景方案；任何价位均为条件判断而非保证的买卖点。
- 实时/竞价价格与日线指标必须标出各自数据时点和口径；未收盘或零成交的当日 K 线
  不得表述为当日收盘价，也不得与最近完整交易日的技术指标混为一谈。

### 证据地基（`deep_cards`）

```
run_skill("stock-analyzer", {"fn": "deep_cards", "kwargs": {"codes": "600519,000858"}})
```

**入口现状（2026-11-26 核实）**：`run_skill` 的技能执行注册表（`scripts/skill_run.py`
EXECUTABLE_SKILLS）目前只放行 `fn=analyze`，`deep_cards` 经 run_skill 调用必报
「fn 不在白名单」——放行前批量证据请逐只 `analyze` 获取；放行 = 在注册表白名单补一个
函数名（一行改动，属技能目录外文件，由维护者执行）。

`deep_cards` 是 deep 层的**批量**入口（自 market-screener 的 deep 层独立演化，见
`_deep.py` 顶部说明）：只取事实、不做判断、不给方向，返回两档

- `analyzed_rank[]`：**全部票**的横向可比字段（价位/均线/支撑压力/封板/量比/连板/资金/风险），不截断；
- `analyzed[]`：满卡，按字符预算截断，**与 rank 同序**（p_up 降序、无预测沉底），故满卡即证据最强的 N 只。
  分两档：前 3 只**标准卡**（全字段），其后为 `card_tier="compact"` 的**精简卡**
  （剔 `tech.support.supports/resists`、`flow.recent`、`shape`，这三类在 rank 行或 `inspect_stock` 里可复得）。

分工：`analyze` 给结论（方向/触发/证伪/价位），`deep_cards` 给批量证据。
`analyze` 内部复用同一份 deep 实现装配单票证据；需要「结论 + 全量证据」时先
`deep_cards`（注册表放行后）再逐只 `analyze`。

字段口径与 market-screener 的 `deep_analyze` **同源不同步**：同一份装配层复制的两个
独立演化副本，`_REPORT_GUIDE` 已各自分叉（逐字一致的只有 `_slim_card`/`_dumps_len`，
量化可复跑 `tmp/review_deep_diff_20261126.py`）——改本技能的 `_deep.py` 不会影响选股
技能，反之亦然。
