# 2026-05-05 工作日志

## 任务：排查 A 股数据混入加密货币数据源问题

### 问题描述
后端日志持续报错：
```
app.data_sources.crypto - WARNING - Symbol '000690' (normalized: 000690/USDT) not found on coinbase.
Error: coinbase GET https://api.coinbase.com/v2/currencies
```
A 股代码 `000690`（南海发展）被错误地发送到 Coinbase（加密货币交易所）拉取行情。

---

### 根因分析

#### Bug 1（主因）：`app/routes/strategy.py` 第 ~806-838 行

**现象**：策略持仓价格刷新时，所有 symbol 无论市场都走 Crypto 数据源。

**代码路径**：
```python
# 第 806 行：SQL 没有 SELECT market 字段
cur.execute("""
    SELECT id, strategy_id, symbol, side, size, entry_price, ...
    FROM qd_strategy_positions WHERE strategy_id = ?
""", (strategy_id,))

# 第 838 行：硬编码 Crypto 数据源
ds = DataSourceFactory.get_source("Crypto")
unique_syms = list({r.get("symbol") for r in rows ...})
# 对所有 symbol 调用 Crypto 的 get_ticker → A 股代码报错
t = ds.get_ticker(sym)
```

**问题链路**：
```
qd_strategy_positions (含 000690, market=CNStock)
  → SELECT 漏查 market 字段
  → DataSourceFactory.get_source("Crypto")  ← 硬编码
  → CryptoDataSource.get_ticker("000690")
  → _normalize_symbol("000690") → "000690/USDT"
  → CCXT coinbase.fetch_ticker("000690/USDT") → 找不到 → 报错
```

**注意**：`qd_strategy_positions` 表**有** `market` 字段（`trading_executor.py:3489` 可见），但 SELECT 没查。

#### Bug 2（次因）：`app/routes/market.py` 第 437 行

**现象**：调用不存在的 `DataSourceFactory.get_batch_tickers()` 方法。

```python
batch_result = DataSourceFactory.get_batch_tickers(market, symbols)  # AttributeError
```

**降级路径**（正确）：catch 后走 `get_single_price(market, sym)` → 正确传了 market。

### 架构现状分析

#### 各层接口名对照

| 层级 | 接口名 | 签名 | 说明 |
|------|--------|------|------|
| **Provider** | `fetch_quotes_batch` | `(codes: List[str], timeout=10) → Dict[str, Dict]` | 腾讯/新浪一次HTTP批量拿，返回 ticker 格式 |
| **Coordinator** | `passthrough` | `(fn, *args, **kwargs) → Any` | 纯透传，不加协调逻辑 |
| **CNStockDataSource** | `get_batch_quotes` | `(symbols: List[str]) → Dict[str, Dict]` | 透传 Provider 批量接口 |
| **CNStockDataSource** | `get_ticker` | `(symbol: str) → Dict[str, Any]` | 支持逗号分隔批量，内部委托 `get_batch_quotes` |
| **CNStockDataSource** | `get_kline` | `(symbol: str, tf, limit, ...) → List[Dict]` | 支持逗号分隔批量，内部委托 `get_kline_batch` |
| **CryptoDataSource** | `get_ticker` | `(symbol: str) → Dict[str, Any]` | 直接调 CCXT（无 Coordinator） |
| **BaseDataSource** | `get_ticker` | `(symbol: str) → Dict[str, Any]` | 抽象基类，单只签名 |
| **DataSourceFactory** | `get_ticker` | `(market: str, symbol: str) → Dict[str, Any]` | 便捷方法，分发到对应 DataSource |
| **DataSourceFactory** | `get_batch_quotes` | `(market: str, symbols: List[str]) → Dict[str, Dict]` | 仅 CNStock 有效，其他返回空 |

#### 各市场数据源实现情况

| 方法 | CNStock | Crypto | USStock | HKStock | Forex | Futures |
|------|:-------:|:------:|:-------:|:-------:|:-----:|:-------:|
| `get_ticker(symbol)` | ✅ Coordinator race | ✅ 直接CCXT | ✅ 直接yfinance | ✅ 直接调用 | ✅ 直接调用 | ✅ 直接调用 |
| `get_kline(symbol,tf,limit)` | ✅ Coordinator queue | ✅ 直接CCXT | ✅ 直接yfinance | ✅ 直接调用 | ✅ 直接调用 | ✅ 直接调用 |
| `get_batch_quotes(symbols)` | ✅ Coordinator passthrough | ❌ | ❌ | ❌ | ❌ | ❌ |
| `get_kline_batch(symbols,...)` | ✅ Coordinator queue | ❌ | ❌ | ❌ | ❌ | ❌ |

**结论**：只有 CNStock 走 Coordinator，其他市场 DataSource 直接调底层库。

#### `get_batch_quotes` 名字歧义

返回格式（以 tencent provider 为例）：
```python
{
    "sh600519": {
        "last": 1800.0,        # ← ticker 格式，不是 OHLCV
        "change": 15.0,
        "changePercent": 0.84,
        "high": 1810.0,
        "low": 1790.0,
        "open": 1795.0,
        "previousClose": 1785.0,
        "name": "贵州茅台",
        "symbol": "sh600519"
    }
}
```
名字叫 `quotes`，实际返回 ticker 格式。调用方容易误判。

### 修复方案

#### 设计原则
1. 不改 base 类签名（`get_ticker(symbol: str)` / `get_kline(symbol, ...)`）
2. CNStock 的 `get_ticker` 和 `get_kline` 支持逗号分隔批量参数
3. 其他市场保持单个传参，兼容主版本
4. 调用方按市场分组，A 股拼逗号一次调用，其他市场逐只循环

#### 改动文件清单

| 文件 | 改动内容 |
|------|---------|
| `app/data_sources/cn_stock.py` | `get_ticker` 检测逗号 → 委托 `get_batch_quotes`；`get_kline` 检测逗号 → 委托 `get_kline_batch` |
| `app/routes/market.py` | CNStock 自选股逗号拼接一次调 `get_ticker`；其他市场逐只调 `get_ticker` |
| `app/routes/strategy.py` | SQL 加 `market` 字段；按市场分组取价，不再硬编码 Crypto |

#### 修复后调用链路

**A 股批量 ticker（market.py）**：
```
market.py: symbols = ["600519", "000001", "000690"]
  → DataSourceFactory.get_ticker("CNStock", "600519,000001,000690")
    → CNStockDataSource.get_ticker("600519,000001,000690")
      → 检测到 ',' → get_batch_quotes(["600519","000001","000690"])
        → Coordinator.passthrough(tencent.fetch_quotes_batch)
          → HTTP GET https://qt.gtimg.cn/q=sh600519,sz000001,sz000690
          → 一次返回全部行情
```

**A 股批量 kline**：
```
DataSourceFactory.get_kline("CNStock", "600519,000001", "1D", 100)
  → CNStockDataSource.get_kline("600519,000001", "1D", 100)
    → 检测到 ',' → get_kline_batch(["600519","000001"], "1D", 100)
      → Coordinator.coordinate_kline(symbols=["600519","000001"], ...)
        → 动态队列多源并发
```

**其他市场单只**：
```
DataSourceFactory.get_ticker("Crypto", "BTC/USDT")
  → CryptoDataSource.get_ticker("BTC/USDT")
    → 无逗号 → 单只模式 → CCXT fetch_ticker
```

**策略持仓（strategy.py）**：
```
qd_strategy_positions: [{symbol:"000690", market:"CNStock"}, {symbol:"BTC/USDT", market:"Crypto"}]
  → 按 market 分组:
    CNStock → ["000690"]  → get_ticker("CNStock", "000690")
    Crypto  → ["BTC/USDT"] → get_ticker("Crypto", "BTC/USDT")
  → 各走各的数据源，不再混入
```

| `get_batch_tickers` | `_get_tickers` | 私有化 |

#### get_kline 重构
**改动前**：单只模式自己调 Coordinator + 写缓存，批量模式调 `_get_klines`，逻辑重复且缓存的是过滤后数据（bug）。

**改动后**：
```
get_kline("600519")           → _get_klines(["600519"])  → filter → return
get_kline("600519,000001")    → _get_klines(["600519","000001"]) → return
```
- 单只/批量统一走 `_get_klines`
- 缓存逻辑只在 `_get_klines` 一处
- `get_kline` 只做分发 + 过滤（before_time / after_time）

#### docstring 完善
- `get_ticker` — 单只/批量用法、实现流程、返回格式
- `get_kline` — 同上

**最终 2 个对外接口**：`get_ticker`、`get_kline`
