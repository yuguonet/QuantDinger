### 3. 数据源复权问题统一（已分析，待执行）

#### 问题本质

整条链路的 `adj`（复权方式）参数是断的。Provider 层支持，但 Coordinator 适配器把 adj 丢掉了，导致上层全部硬编码 `qfq`（前复权），用户无法选择复权方式。

#### 数据流追踪（adj 在哪里断的）

```
routes/kline.py:get_kline()                    ← 无 adj 参数，不传
    ↓
services/kline.py:get_kline()                  ← 无 adj 参数，不传
    ↓
data_sources/factory.py:get_kline()            ← 无 adj 参数，不传
    ↓
data_sources/cn_stock.py:get_kline()           ← 无 adj 参数，不传
    ↓
coordinator.py:coordinate_kline()              ← 无 adj 参数，不传
    ↓
coordinator.py:_make_provider_fetch_fn()       ← ⚠️ adj 在这里被丢掉！
    ↓                                               provider.fetch_kline(code, tf, limit)
    ↓                                               实际签名是 fetch_kline(code, tf, count, adj="qfq", timeout=10)
    ↓                                               但适配器只传了 3 个参数，adj 用默认值 "qfq"
    ↓
provider/*.py:fetch_kline(code, tf, count, adj="qfq")  ← 支持 adj，但永远收到默认值
```

#### 注意事项

1. **缓存 key 必须包含 adj**: 不同复权方式的数据不能共用缓存。`generate_kline_cache_key` 需要加 adj 参数。
2. **默认值保持 "qfq"**: 所有新增参数默认 `adj="qfq"`，保持向后兼容。
3. **前端交互**: 需要确认前端如何暴露复权选择（K线图下拉菜单 / 设置面板）。
4. **周线/月线聚合**: 由日线聚合时，日线的 adj 必须和请求的 adj 一致。
5. **批量接口**: `fetch_kline_batch` 也需要传递 adj（Provider 签名已支持）。
6. **其他数据源**: us_stock / crypto / forex / futures / hk_stock 也需要加 adj 参数（如果对应的 Provider 支持的话）。
