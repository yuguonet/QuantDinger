# 诊断：前端自选股列表不显示股票

## 问题描述
数据库 `qd_watchlist` 表中有数据，但前端自选股列表不显示。

## 数据流概览
```
WatchlistPanel.created()
  → loadUserInfo()    // 异步，设置 this.userId
  → loadWatchlist()   // 异步，调用 API 获取列表
    → GET /api/market/watchlist/get?userid=N
      → SELECT ... FROM qd_watchlist WHERE user_id = ?
      → 返回 { code: 1, data: [...] }
  → visibleWatchlist (computed) 按 currentGroup 过滤显示
```

## 可能原因（按概率排序）

### 原因1: 分组过滤导致数据不可见（最可能）
- 前端 `visibleWatchlist` 按 `currentGroup` 过滤，默认值为 `'默认自选'`
- 龙回头Pro策略自动管理的股票，其 `group_name = '龙回头Pro'`
- 如果用户当前选中的是 `'默认自选'` 分组，而数据在其他分组，则不显示
- **验证方法**: 检查前端 WatchlistPanel 的分组下拉框是否有其他分组

### 原因2: 用户ID不匹配
- 前端 `this.userId` 初始化为 `1`（line 444）
- 后端使用 `g.user_id`（由 `@login_required` 装饰器从 JWT/Session 解析）
- 如果数据库中的 `user_id` 不是当前登录用户，查询返回空
- **验证方法**: 检查数据库中 `user_id` 值 vs 前端请求的 `userid` 参数

### 原因3: API响应异常
- 前端检查 `res && res.code === 1 && res.data`
- 如果后端抛异常返回 `code: 0`，前端不会设置 `this.watchlist`
- 错误被 `catch (error) { /* silent */ }` 吞掉，无任何提示
- **验证方法**: 浏览器 F12 → Network → 查看 `/api/market/watchlist/get` 响应

### 原因4: 前端时序问题
- `created()` 中 `loadUserInfo()` 和 `loadWatchlist()` 同时触发
- `loadWatchlist()` 第一次执行时 `this.userId = 1`（默认值），会立即查询
- `loadUserInfo()` 完成后再次调用 `loadWatchlist()`，使用正确的 userId
- 如果登录用户 ID ≠ 1，第一次查询返回空，第二次才正确
- 但最终结果应该正确（第二次覆盖），除非有竞态问题

## 诊断步骤（只读，不修改任何内容）

### Step 1: 检查 API 响应
1. 打开浏览器 F12 → Network 标签
2. 访问包含自选股的页面
3. 找到 `/api/market/watchlist/get` 请求
4. 检查：
   - HTTP 状态码是否 200
   - 响应体中 `code` 是否为 `1`
   - `data` 数组是否有内容
   - 数组中每个元素的 `group_name` 值是什么

### Step 2: 检查数据库数据
```sql
-- 查看 qd_watchlist 表内容
SELECT id, user_id, market, symbol, name, group_name, strategy_state
FROM qd_watchlist
ORDER BY id DESC
LIMIT 20;
```
重点关注：
- `user_id` 的值（应与登录用户一致）
- `group_name` 的值（是否为 '默认自选'、'龙回头Pro' 或其他）

### Step 3: 检查前端分组状态
在浏览器 Console 中执行：
```js
// 获取 WatchlistPanel 组件实例
document.querySelector('.watchlist-panel').__vue__
```
检查：
- `watchlist` 数组是否有数据
- `currentGroup` 的值是什么
- `visibleWatchlist` 的长度
- `watchlistGroups` 的内容

### Step 4: 检查后端日志
查看后端控制台是否有 `get_watchlist failed` 错误日志。
